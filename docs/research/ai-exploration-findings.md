# 寻路与 Fairy 代行：隔离算法探索

> 日期：2026-10-30。状态：隔离实验与浏览器交互检查已完成，待人工观察确认；研究结论不替代正式玩法决议或 T10/T11 验收。
> 本轮只新增隔离原型和研究材料，不修改既有战斗模拟器、正式规格或用户已有改动。

## 1. 回答什么问题

1. 在相同四秒起点、候选集合与翻向执行语义下，短时前瞻和字典序安全筛选是否改善实际表现？
2. 全候选精评与「粗筛后仅精评四个动作」相比，后者省多少工作，又会丢掉多少效果？
3. 积分相对角速度代理排序，能否代表有限一秒内的几何命中排序？
4. 现有流场后继是否遵循已经算出的加权最短路距离？共享单源搜索是否值得继续验证？

这里的完整精评，只是**固定候选集合、有限时域、当前预测模型内的参考**，不叫全局最优。

## 2. 现有事实与研究建议分开

- 正式设计要求四秒代行、玩家同等数值、P0–P3 优先级与可复现；来源：[玩法设计 §4.5](../design/game-design.md#45-fairy-代行技能)、[算法规格](../specs/ai.md)。
- 现有 Fairy 是十六方向、0.25 秒恒速端点评分的占位策略，没有一秒前瞻或 P0–P3；来源：[基线规划器](../../prototype/battlesim/src/Fairy/BaselinePlanner.cs#L7-L24)。
- 原执行链每六 tick 更新 Fairy 命令，每 tick 使用它；`RequestReverse` 是被持续读取的布尔值，而不是自动消费一次的事件。组合两 tick 翻向冷却，可静态推导一次命令会发生重复翻向；本报告不把静态推导称作已经跑过的重现。来源：[执行链](../../prototype/battlesim/src/Sim/BattleSimulation.cs#L126-L182)、[时间常量](../../prototype/battlesim/src/Core/SimConstants.cs#L13-L29)。
- 原 A* 的平滑使用固定 0.3 通行余量，玩家半径为 0.4；平滑检查与实际圆墙运动也不是完全相同的几何模型。来源：[A* 平滑](../../prototype/battlesim/src/Nav/AStar.cs#L149-L179)、[玩家](../../prototype/battlesim/src/Combat/Player.cs#L8-L23)、[网格检查与碰撞](../../prototype/battlesim/src/Nav/Grid.cs#L63-L164)。
- 当前快照含玩家速度，但没有敌人速度、状态持续时间、玩家翻向冷却等完整预测信息；来源：[快照](../../prototype/battlesim/src/Fairy/IPlanner.cs#L33-L109)。不能声称已实现精确世界预测，更不能读取未来刷新、随机数或隐藏目标补齐。
- 当前性能统计只计脚本与 Fairy 的 `Decide`，不含快照、流场、敌人寻路和分离。因此不能从原 `avgDecisionMs` 宣称整帧 AI 达到 2ms。来源：[计时接缝](../../prototype/battlesim/src/Sim/BattleSimulation.cs#L126-L143)。

## 3. 实验方法

实验代码位于 [隔离目录](../../prototype/ai-exploration/README.md)，以项目引用复用现有 [BattleSim 项目](../../prototype/battlesim/BattleSim.csproj)。实际伤害、命中、运动与敌人更新仍由原 [BattleSimulation](../../prototype/battlesim/src/Sim/BattleSimulation.cs) 执行，不修改其规则。

### 3.1 控制变量

- 各策略使用相同场景、种子、初始状态、刷怪序列与动作集合。
- 各策略只输出期望旋转方向，`RequestReverse=false`，排除重复翻向这个共同执行问题。
- `greedy` 是同候选集合上的短视加权对照，不是原 `BaselinePlanner` 的逐字复刻；收益不可直接写成「比现有正式算法提高多少」。
- `lex-full` 对候选做完整短轨迹前瞻，再按预测伤害、覆盖代理、有效输出代理与连续性筛选。覆盖代理使用以刀环半径为峰、宽度 0.65 的三角距离核积分，不等同正式规格的硬阈值环带驻留指标；V 加入敌我相对速度和可命中环带门控，分母仍取固定环半径近似。
- `lex-coarse4` 与完整精评保持同样动作集合和精评规则，但先粗评，再仅精评四个动作；这是**有损 top-k**，不是可证明等价的剪枝。
- 预测复用现有运动学与网格碰撞。敌人预测仍是基于可见状态/历史的简化模型，不等同真实敌人状态机。
- 战斗场景通过公开 `Scenario` 输入建立；敌人、弹丸与落区由原状态机自然推进，`Trace` 只记录。独立相位扫描是明确标注的几何小模型，与真实战斗结果分开统计。
- 每组重复运行，以逐 tick 哈希检查确定性；耗时只进入报告，不回流进世界或决策。

### 3.2 相对角速度的适用条件

设敌我相对位置 `q = e - p`，距离 `d = |q|`，逆时针单位切向 `t = Perp(q / d)`。敌人方位角速度为：

```text
θdot = ((ve - vp) · t) / d
真实相对扫角速度 = |sΩ - θdot|
                 = |Ω + s ((vp - ve) · t) / d|
```

该推导使用现有 [Perpendicular 约定](../../prototype/battlesim/src/Core/Vec2.cs#L36-L37)与[刀相位推进规则](../../prototype/battlesim/src/Combat/BladeRing.cs#L29-L35)。因此当前 `|Ω + s(vcmd · t)/r|` 只有在敌人近似静止、距离接近刀环半径、真实速度接近期望速度时才是相应近似，而非简单的正负号错误。

有限窗口内的命中还取决于初始相位、径向离环、敌人半径、目标死亡和每刀冷却。独立几何扫描使用一秒、持续存活的目标与匀速运动；真实战斗对照使用四秒代行，两者分开解释。实际判定来源：[逐刀检测与冷却](../../prototype/battlesim/src/Sim/BattleSimulation.cs#L185-L227)、[伤害常量](../../prototype/battlesim/src/Combat/DamageRules.cs#L10-L16)。本轮扫描用于检验代理排序，不用于另定伤害公式。

### 3.3 导航对照的边界

[导航探针](../../prototype/ai-exploration/NavigationProbe.cs)读取现有混战地图，对原流场每个可达格的后继计算：

```text
选中后继的代价 = edgeCost(current, next) + referenceDistance[next]
局部额外代价 = 选中后继的代价 - referenceDistance[current]
```

参考搜索与原导航一样使用八邻接、直行 1、斜行 √2，以及任一正交格堵塞即禁止对角的规则。距离仍下降的非最短后继不等于循环，也不等于所有地图都会出现肉眼可见的绕路。

逐点 A* 与单源树计时**不等价**：原 A* 包含路径平滑与采样检查；实验树包含分配与回溯，但不平滑。因此只报告观测，不报告为等价输出的加速比。半径 0.4 采样拒绝数也只是诊断，不直接证明实体一定撞墙。

## 4. 实测结果

### 4.1 四秒真实战斗

每格为「命中数 / 实际掉血 HP」。三个策略使用同一场景输入，结果来自原模拟器。

| 场景 | 短视加权 | 完整分层前瞻 | 粗筛 + 前四精评 |
| --- | ---: | ---: | ---: |
| 单敌追踪 | 3 / 0 | 3 / 0 | 3 / 0 |
| 近墙转向 | 6 / 0 | 6 / 0 | 6 / 0 |
| 弹丸与落区 | 3 / 12 | 5 / 0 | 5 / 0 |
| 混合敌人 | 12 / 0 | 9 / 15 | 10 / 0 |
| 拥挤陷阱 | 22 / 13.867 | 24 / 7.067 | 22 / 7.067 |

**观察**：前瞻在弹丸/落区场景同时改善命中和掉血，在拥挤场景降低掉血，但并非单调优于短视策略。不能从五个小场景平均出一个全游戏提升率，更不能视为已满足正式基线提升 20% 的验收。

### 4.2 混战反例：搜索更多，预测仍会失配

完整前瞻在 tick 234 选中动作的预测损失为 0；当时真实撞针处于 `Windup`。tick 240 的最小预测损失已变为 15，真实世界也在该 tick 由 100 HP 变为 85 HP，撞针处于 `Dash`。

证据：[tick 234 决策](../../prototype/ai-exploration/results/mixed.lex-full.decisions.json#L26721-L26725)、[tick 234 敌人状态](../../prototype/ai-exploration/results/mixed.lex-full.trace.json#L13652-L13675)、[tick 240 决策](../../prototype/ai-exploration/results/mixed.lex-full.decisions.json#L27424-L27428)、[受伤帧](../../prototype/ai-exploration/results/mixed.lex-full.trace.json#L13976-L13999)。

_注：逐 tick 轨迹与决策文件属运行证据，体积大且可重建，未入库；按 README 的 `--out` 命令重跑同一场景与种子可复现，确定性见 `results/summary.json` 的 `determinism` 段。_

预测实现对预警状态按静止外推、没有未来状态切换；这与反例相符。**尚未做单因素消融，不能把全部损失唯一归因于这一个因素。** 可确认的是：当前预测零损失并不保证随后六 tick 无伤，增加候选精评本身不能补足缺失的预警进度。

### 4.3 输出代理与实际几何命中

独立一秒扫描共有 216 个距离/敌速/相位组合，每组十个动作：

- 88 组（40.74%）按积分输出代理选出的动作未达到候选中的最高几何命中；128 组达到最高命中。
- 最大少命中 5 次，平均少命中约 0.648 次。这是受控输入集合上的枚举差异，不是统计置信结论。
- 例子：初始距离 3、敌人切向速度 −2.6、初始相位 π/8。沿 +X 移动时，代理较高的旋转方向命中 2 次，另一方向命中 7 次；最高代理约 2.049，七命中的动作代理约 0.179。

该探针已经用实际移动速度与环带门控积分，仍未使用刀相位来选择动作。结果支持「V 是便宜代理，不能直接等同有限窗口命中」；不支持将其全盘删除或直接推广到完整战斗。

另一个规则事实是：原命中按每刀冷却检测，目标仍在刀尖范围内时，冷却结束即可再次命中。它不是严格的「每次穿越只结算一次」。若玩法要求 DPS 与扫过频率严格成正比，需要先确认这一伤害语义，再选择 P2；本轮没有改动伤害规则。

### 4.4 粗筛的质量与成本

粗筛组保留全部 60Hz 运动和已知危险处理，仅降低覆盖/输出代理采样。前三个场景与完整组结果相同；拥挤场景少 2 次命中，混战场景则因选择不同而避开完整组所受的 15 点伤害。这不证明粗筛天然更安全。

- 覆盖/输出检查次数减少约 71.7%–72.2%；精评动作由每轮 36 个降至 4 个。
- 移动推进次数没有减少；部分危险/接触工作会随两组执行后不同的世界状态而变化。
- 排序、分配与共同的危险处理仍有成本；不能将 72% 的某类检查减少写成 72% 总体提速。本机分项分位数见[原始汇总](../../prototype/ai-exploration/results/summary.json)。

因此现阶段把完整组留作有限模型参考，把粗筛组保留为近似对照；没有证据支持直接采用 top-4 作为正式默认。

### 4.5 导航：本轮没有支持立即更换搜索方式

在原混战地图的 931 个可达非根格中，未测到原流场后继的额外图代价；远端示例的原路线与参考最短路线代价均约 26.213。这个结果只针对这张地图，既不证明所有拓扑都等价，也不能把先前静态疑点写成已经复现的路径错误。

候选从源点图距离 2–8 的格中固定选择。以下为 31 次本机观测的 P50：

| 候选数 | 原逐点 A* / ms | 实验全图单源树 + 回溯 / ms |
| --- | ---: | ---: |
| 4 | 0.0139 | 0.2825 |
| 12 | 0.0561 | 0.2775 |
| 20 | 0.1042 | 0.2751 |

实验树展开 932 格；近目标 A* 可以更早结束。**两者平滑、分配与数据结构不同，不能给出算法级加速比。** 但本结果足以否定「候选一多就应该立即把现有路径搜索换成每轮全图树」这个落地前提。后续只有在候选分布、缓存复用或路径批量成本出现实测需求时，再比较早停单源树与一致平滑的版本。

本轮选出的路径也没有被半径 0.4 采样检查拒绝；这不消除代码中固定 0.3 平滑余量与玩家半径不一致的事实，更不等于所有路径已获物理可通行证明。

### 4.6 可复现与页面检查

15 个场景×策略组合，每组预热 3 次、测量 7 次，并额外运行一次导出。每组七次测量与导出记录逐 tick 哈希一致；导出共 3,615 帧、600 次决策。哈希量化与隐藏状态范围仍沿用原模拟器。

临时 Edge 无头浏览器实际点击了全部十五组场景/策略，核对首次规划、36 个候选、候选预览、安全容差沙盘、逐决策前进与末帧；导航与相位视图分别核对三行对照和十个动作，没有运行时脚本异常。检查记录：[browser-inspection.json](../../prototype/ai-exploration/results/browser-inspection.json)。截图已生成，但没有完成像素级视觉审核。

## 5. 决策与落地建议

当前推荐不是直接采用某一实验策略，而是分三个小步骤推进：

1. **先统一执行和伤害语义。** 期望旋转方向应是幂等持有指令；一次性翻向事件应只消费一次。路径平滑按执行角色半径检查，替换末段时验证实际新线段。另确认 P2 要最大化「扫过机会」还是现有冷却规则下的实际命中；这些契约比增加搜索量更优先。
2. **以混战受伤帧为下一原型问题。** 在同一快照接缝补足玩家确实能观察到的预警进度、速度与已锁定方向；对尚未锁定或首次观测的信息保留不确定性。验证 Windup→Dash 的发生窗口、朝向与撞墙过程，而不是把 Windup 当作未来一秒持续静止。只针对这个已观察反例做消融，比较实际损失、预测误差与候选选择。
3. **保留现有导航，先做按需工作。** 复用路径缓存、目标格未变时跳过相同流场重算、不可达请求固定 tick 退避与确定性配额轮转。完整前瞻继续做参考，粗筛先保持近似实验身份；达到具体性能瓶颈后，再考虑有明确损失下界的短路，或仅压缩低优先级评价的采样。

### 下一轮只做一个最小实验

复用本轮 `mixed` 输入与真实执行链，只改变敌人预警转冲锋预测：

- A：当前恒速/静止预测。
- B：从合法观测历史估计预警发生窗口，模拟冲锋与墙体约束；无法确定时报告误差区间。
- 保持候选、P0/P1/P2、前瞻长度和伤害规则不变。
- 比较四秒实际掉血、逐次规划的未来六 tick 损失漏判，以及本机决策耗时；不得通过读取未来脚本或隐藏随机结果使 B 获胜。

当这个问题回答清楚后，再单独比较「V 精评」与「带相位/每刀冷却的短时命中精评」。两者不要与更换导航、重调全部权重同时进行，以免无法辨认收益来源。

## 7. 限制与尚未回答

- 小规模、有限场景与固定种子不代表全关卡表现；不能据此宣称「可存活场景必无伤」或满足正式验收的 20% 输出提升。
- 一秒局部前瞻不保证避开一秒以外的死角或三秒后落区；终态逃生裕量、绕障目标与更长时域应在具体失败场景出现后单独比较。
- 预测零伤害只是在当前模型与候选集合下的判断；快照缺失与未建模行为仍会产生误差。零伤候选优先与 2% 微伤容差不是同一个目标，正式规格需人工确认。
- 未实现道具、完整 Boss、Unity 表现或 Android 实测；不把这些缺失补成虚构结论。
- 一手来源研究记录于 [资料报告](ai-navigation-planning-sources.md)。搜索插件认证失败时改为直接抓取已知官方/作者 URL；不把未读取资料当作已验证。
- 工作区已有大量与本轮无关的未提交内容。本轮不切换分支、不自动提交、不推送，也不把实验外壳混入正式算法。待人工看过原型、确认结论后，再按 [PlasticSCM 工作流](../agents/plastic-workflow.md)捕获探索分支与任务指针。
