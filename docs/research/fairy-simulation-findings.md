# Fairy 安全边界内输出走位：隔离模拟结果

> 日期：2026-10-30。状态：已实际运行隔离模拟与浏览器交互观察，待人工体验；不是正式玩法验收、全局最优或移动端性能证明。
> 用户目标：预测不受伤的边界内尽量提高飞刀 DPS，输出相当时顺路拾取；翻向独立，不修改移动路线。
> 版本说明：第 1–6 节记录引入三类道具前的历史批次（160 条评估、40 次复跑）；道具增量见第 7 节；单钉枪零输出接敌修复见第 8 节；当前远程身体接触、震开与受伤保护见第 9 节。各版旧批次仅作历史证据，不用于评价新增规则。

## 1. 本轮结论

1. **预测攻击阶段值得保留。** 同为一秒前瞻，恒速外推组在 32 个场景起点累计掉血 96，阶段组为 0；但阶段组不是每个场景都输出更高。
2. **安全前瞻与输出评价不宜默认共用同一时域。** 保持一秒安全检查、仅把输出积分缩到 0.25 秒，在冲锋、空降和召唤探针明显增加了这批样本的真实刀刃输出。
3. **短输出窗口也有具体反例。** 远程场景平均伤害从 92.5 降到 60；初始观察下所有短窗输出分为零，候选选择停留，而一秒输出评价主动接敌。
4. 当前保留“一秒安全＋短期输出”作为有价值的研究候选，同时保留长窗与短窗对照；**没有选出覆盖所有场景的最终默认算法，也没有证据要求先引入机器学习。**

可以双击 [Fairy 单文件原型](<../../prototype/enemy-behavior/fairy-response.prototype.html>)，在同一场景/种子下切换策略、查看四步引导、候选预测与实际结算。

## 2. 世界与信息合同

### 复用与必要补缺

[模型构建器](<../../prototype/enemy-behavior/build-fairy-response.prototype.cjs>)读取现有 [敌人原型](<../../prototype/enemy-behavior/enemy-behavior.prototype.html>) 的纯 EnemyLab 脚本，复用圆形几何、Dijkstra/A*、局部移动与攻击状态机，派生本轮隔离规则。真实执行与阶段预测运行同一份派生模型；原敌人体验页、正式 C# 模拟器和正式规格没有修改。

新增结算：尾灯持续接近；尾灯/撞针任意阶段身体接触时一次扣血并自毁，不等待攻击许可。飞刀与接触事件按本 tick 内相对扫掠的首次相交时间排序，同刻接触优先；刀刃每刀对每目标有独立冷却。击杀与接触自毁分别统计，已有弹丸/落区不随攻击者死亡隐式消失。

| 项目 | 本轮实验值与来源 |

| 世界步长 / 决策间隔 | 1/60s / 6 tick（0.1s） |
| 玩家半径 / 移速 / 加速度 | 0.36 / 4 / 40，沿用 JS 模型 |
| 飞刀 | 四刀、半径 2、角速度 2.5、单刀伤害 10、命中冷却 6 tick；数值参考既有 C# 原型 |

| Boss 周边新对象 | 第 90 tick 在生成源周边新增三只普通小怪；只验证动态实体接入，不实现完整 Boss/血量触发 |

### 合法观察与预测近似

`observe`只输出当前位置/速度、可见 HP、攻击阶段与公开倒计时/方向、现有弹丸/落区/道具，以及静态地图。`fromObservation`从这些字段重建预测世界，**不复制未来刷新表、随机状态、隐藏路径、站位或导航更新时钟**。新怪下一次可见观察自然加入。

当前原型已显示阶段剩余时间与锁定线，可供精确观察；正式表现若不提供同等精度，需要另测历史推断误差。来源：[已有可见信号](<../../prototype/enemy-behavior/enemy-behavior.prototype.html#L163-L182>)。

预先保留的限制：

- 共享规则不等于共享完整隐藏状态。重建路径/flow 时钟、首次看到的弹丸寿命可能失配。
- 预测禁用刀刃伤害，不把未来抢先击杀当作安全依据。这是明确的保守近似，可能低估能安全输出的动作。
- 所有候选都是有限时域内恒定移动输入；A* 引导只生成当前方向，不把尚未执行的整条折线路径当作已经发生。
- 移动代理固定参考旋向 +1；旋向控制独立考察已选移动的前 6 tick。它不反馈改路，不宣称获得移动/旋向联合全局最优。

## 3. 对照矩阵与测量口径

[规划器](<../../prototype/enemy-behavior/fairy-planner.prototype.js>)每轮使用 16 等角方向、停止、当前方向，再加最多四个公开敌人刀环/道具引导，共不超过 22 个候选。先最小预测损失（有零伤就优先零伤），再最大输出积分，接着拾取、连续性与稳定 ID；安全余量不优先压过输出。

| 标识 | 敌人预测 | 安全预测 | 输出积分 |
| --- | --- | ---: | ---: |
| `greedy` | 恒速，无未来攻击阶段转换 | 0.25s | 0.25s |
| `linear` | 恒速，无未来攻击阶段转换 | 1s | 1s |
| `phase` | 公开观察重建并推进状态机 | 1s | 1s |
| `phase-short` | 同上 | 0.25s | 0.25s |
| `phase-near` | 同上 | 1s | 0.25s |

输出代理为可命中环带内相对扫角速度的时间积分，使用实际预测速度；实际输出另按真实刀尖命中、目标 HP 与冷却结算，不把代理数值直接当成实测伤害。安全和拾取时域在 `phase-near` 中仍为一秒。相对速度代理的适用边界见[此前检验](<ai-exploration-findings.md#L90-L100>)。

实验输入：八类小场景 × 四个种子起点，每场固定四秒。种子 1 为标准起点，其他种子只对位置作小扰动（每轴约 ±0.2）并改变召唤角度；不是四张独立地图。

- 基础批：八场景 × 四起点 × 三策略 = **96 条评估记录**。
- 时域补充：冲锋、空降、混合、墙边四场景 × 四起点 × 三个阶段变体 = **48 条记录**，含 16 条重复的 `phase` 控制条件。
- 追加确认：其余四场景 × 四起点 × `phase-near` = **16 条记录**。
- 合计 **160 条评估记录、144 个不同条件**；另做 **40 次同机重复运行**。不将预热、pilot 或浏览器点击重复算成独立样本。

原始输入/指标与配置：[基础汇总](<../../prototype/enemy-behavior/fairy-results/summary.json>)、[时域补充](<../../prototype/enemy-behavior/fairy-results/followup/summary.json>)、[追加确认](<../../prototype/enemy-behavior/fairy-results/confirmation/summary.json>)。轨迹与逐决策数据：[基础示例](<../../prototype/enemy-behavior/fairy-results/examples.json>)、[补充示例](<../../prototype/enemy-behavior/fairy-results/followup/examples.json>)。

预测漏判只比较下一次决策前的六 tick（命令持有期）；完整一秒之后实际控制已经改变，不能直接拿其差异当作同一动作的模型误差。掉血使用累计伤害，不以回血后的净 HP 抵消受击。

## 4. 实测结果

以下每格是四个起点的**四秒实际刀刃伤害均值**。累计掉血另外列出；表格不是代理积分或理论 DPS。若需换成四秒平均 DPS，各值除以 4。

| 场景 | 恒速 1s | 阶段：安全/输出 1s | 阶段：安全 1s/输出 0.25s |
| --- | ---: | ---: | ---: |
| 弹丸与射击 | 97.5 | 92.5 | 60 |
| 预警转冲锋 | 57.5 | 75 | 142.5 |
| 空降落区 | 90 | 75 | 115 |
| 混合职责 | 110 | 92.5 | 95 |
| 墙边通路 | 60 | 102.5 | 97.5 |
| 三秒公开落区 | 52.5 | 60 | 60 |
| 生成源周边新对象 | 87.5 | 77.5 | 105 |
| 输出与拾取 | 60 | 60 | 60 |

安全与拾取的汇总按相同的 32 个场景起点计算：

| 策略 | 累计掉血 | 刀刃伤害合计 | 击杀 | 拾取 | 前六 tick 零伤漏判 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 恒速 0.25s | 22 | 2690 | 33 | 4 | 0 |
| 恒速 1s | 96 | 2460 | 23 | 8 | 2 |
| 阶段 1s/1s | 0 | 2540 | 21 | 8 | 0 |
| 阶段 1s/0.25s | 0 | 2940 | 41 | 7 | 0 |

所有这些样本均存活。两种一秒安全阶段策略在这组起点都没有实际扣血；这只是观测，不是安全证明。短输出组相对长输出组汇总增加 400 点伤害（约 15.7%），但射击场景明显退化，不能写成全游戏普遍提升。

### 输出时域的反例与边界

保持一秒阶段预测，把输出积分缩到 0.25 秒，冲锋由 75 增至 142.5，空降由 75 增至 115；墙边则由 102.5 降至 97.5。

如果把安全时域也缩成 0.25 秒，四个补充场景伤害为 **150 / 115 / 100 / 65**，本批仍零伤，但墙边退化明显。不能仅从前三类场景更高的输出就采用统一短安全时域。

射击场景标准起点的单次共同观察探针：

- 一秒输出组选择 `dir:06`，预测输出积分约 5.804，安全候选 13 个。
- 短输出组全部候选的前 0.25 秒输出积分为零，安全候选仍是 13 个；最终选择 `current`，移动为零。

这证实一个局部机制：尚不能在短窗内命中时，纯短窗积分会缺少主动接敌信号；它并不单独证明后续所有输出差异的因果来源。下一轮可保持同一安全检查，对稍远期输出使用折扣而不是完全截断，单独检验是否恢复接敌，同时保留近场输出优势。

## 5. 复现、交互与成本

40 次重复运行的指令/可见状态摘要哈希全部一致；补充批的 16 个 `phase` 控制条件也与基础批逐局哈希一致。哈希覆盖玩家、敌人、弹丸、落区、道具、统计和命令，不覆盖全部隐藏导航状态，不是跨平台位级证明。初始基线的匹配源码已留在 [基线源码快照](<../../prototype/enemy-behavior/fairy-results/baseline-sources.json>)，各批记录模型/规划器 SHA-256。

合同探针均为真：移动及候选分数不随观察中的旋向/刀相位变化；独立翻向不修改观察与移动；未来刷新表不在观察内；移除对象后新 ID 继续单调增长。共同观察点上 `phase` 与 `phase-near` 的安全轨迹/伤害一致，仅输出积分窗口不同。

临时 Edge 实际操作 **五策略 × 八场景 = 40 组四秒引导**，另操作四步引导、定步、四类加入按钮、旋向/种子切换与键盘。36 组具有对应 Node 种子 1 记录的场景，其时间、HP、掉血、伤害、拾取和新增对象数全部一致；另外四组仅属于浏览器观察。未记录脚本异常，760px 视口的文档宽度为 745px。记录：[浏览器观察](<../../prototype/enemy-behavior/inspection/fairy-browser-observations.json>)。截图已生成，但当前模型不支持读取图片，未完成像素级视觉审核。

本机环境：Windows、Node v24.21.0、AMD Ryzen 9 8945HX。每轮计时包括观察构造、移动规划与独立翻向：

| 策略 | 本批平均每轮 / ms | 各局 P95 范围 / ms |
| --- | ---: | ---: |
| 恒速 0.25s | 9.55 | 8.22–13.51 |
| 恒速 1s | 28.20 | 25.03–37.66 |
| 阶段 1s/1s | 78.52 | 24.66–193.22 |
| 阶段 1s/0.25s | 72.77 | 24.43–194.58 |

不是整体合并 P95，也不是手机测量。表中每轮计时不包含真实世界步进、哈希或轨迹导出；原始 `wholeRunMs` 另含这些工作，但不含世界构造。VM 包装与不同轨迹中剩余对象数会影响成本，不同闭环轨迹的耗时不能当作同输入算法加速比。一秒安全仍每候选推进最多 60 tick，短输出评分不会自动减少安全模拟工作。当前实现未证明达到 2ms 预算。

## 6. 下一轮只推进一个问题

优先保留状态转换预测，比较“近场输出＋少量折扣远期输出”与当前两个输出窗口；候选、世界规则、安全时域、拾取和旋向控制保持相同。先回答射击场景的零分停留，避免同时换导航、训练策略或增加全部候选。

后续若出现必须先转弯再输出的具体反例，再比较两段移动；若长预警场景出现明确来不及退出的轨迹，再比较事件期限约束。现有三秒探针未产生掉血，不能据此宣称已解决任意长预警/狭道封锁。

完整 Boss、道具成长/能量、正式信息展示、更多地图/起点及 Android 性能仍未覆盖。研究候选待人手体验后再决定正式吸收范围；不以这些有限结果证明四秒无伤或全局最优。

本轮未切分支、提交或推送，保留工作区原有改动。既定 Plastic CLI 路径当前不存在；待人工确认吸收范围后按仓库权威历史流程捕获材料，不以 Git 提交替代 Plastic 开发节点。

## 7. 三类道具增量（2026-10-30—31）

### 范围与规则来源

本轮按用户要求在原 Fairy 派生模型中引入飞刀、血包、能量球；仍复用 EnemyLab，不修改原敌人体验页、C# 模拟器或正式规格。五种移动策略、安全 / 输出窗口和独立翻向结构不变。前述“近场输出＋折扣远期输出”建议仍未实现，不能将本轮结果归因于它。

| 项目 | 本轮行为 | 来源与边界 |
| --- | --- | --- |
| 飞刀 | 未满时实际 +1 把；满刀不消耗，留原地 | 用户确认满刀行为；[既有设计](<../design/game-design.md#L133-L142>)区分加当前刀数与上限成长。本原型初始 4、固定容量 10，不做上限升级、磨损或内圈 |
| 血包 | 生命比例严格 `<40%` 时，有效回复在道具层内优先 | [既有拾取优先级](<../design/game-design.md#L75-L82>)；不越过安全 / 输出层。每枚 20 HP、满血仍消耗沿用旧原型，尚非正式定值 |
| 能量球 | 触碰消耗；代行期间不回能，规划收益始终 0 | 用户确认；本页全程视为代行，手动模式也只是调试输入，不模拟技能结束后的普通战斗 |

[共享模型](<../../prototype/enemy-behavior/build-fairy-response.prototype.cjs>)的 `itemBenefit` 同时服务真实结算与候选引导。候选仍先比较累计受击与输出；道具层依次比较“低血有效回复 → 实际加刀 → 总有效回复”，不是用总消耗数相加。能量球、满刀飞刀、满血血包不占道具引导名额。实际消耗分类、增加刀数与有效回复分开记录。

新增刀数会进入真实刀尖循环、每敌逐刀冷却和输出代理；普通拾刀保留旧刀冷却，仅为新刀补槽。实验刀数设置也保留已有槽值。拾取沿用原型距离 `0.36 + 0.2`，没有顺带改成设计稿中的 0.6。

### 行为观察

在种子 1、阶段一秒策略的等距道具共同观察下：

- 30 / 39 HP 选择朝血包移动，低血有效回复 20；40 HP 选择朝飞刀移动，预测加刀 1，低血回复分为 0。
- 脚下满刀探针前进一帧：能量球消耗 1、能量仍为 0，飞刀仍在原地且不计消耗；设置 9 刀后再前进一帧，刀数变 10、该飞刀消失。
- 只有能量球与没有道具的配对公开观察，选中移动相同，能量球无专属引导候选。
- 危险血包的直接引导预测受击 14；选中安全侧加刀轨迹预测受击 0，不用 20 HP 回复抵消受击。
- 97 HP 拾取只计 3 有效回复；满血仍消耗但回复为 0。隔离落区探针中，30 HP 受击 14 后回 20，最终 36 HP，累计受击仍是 14；致死后不由同 tick 血包复活。

这些是独立的小探针，不计作下面批量记录的额外独立样本。

### 当前规则批次与回归

[道具版结果](<../../prototype/enemy-behavior/fairy-results/pickups/summary.json>)实际运行 **11 场景 × 5 策略 × 2 种子 = 110 条评估记录**，每局四秒；另对每个场景 / 策略的种子 1 复跑，共 **55 次**，可见状态 / 命令哈希全部一致。五项既有合同探针均为真，包括旋向独立、预测不修改输入观察、未来刷新表不公开和敌人 ID 单调。

原七个无道具场景中，与历史批次具有相同场景 / 策略 / 种子的 **64 条记录**逐项比较 tick、HP、累计受击、实际刀刃伤害、命中、击杀、接触自毁、拾取、有效回复、新对象和前缀零伤漏判，均无差异。新增字段会改变摘要哈希，因此这里比较物理指标，不声称新旧哈希相同。原“输出与拾取”已改输入和结算，不列入此回归对照。

## 8. 单钉枪零输出接敌修复（2026-10-31）

### 用户症状与可运行复现

用户反馈：只剩一个钉枪时，Fairy 不接敌消灭它，而是不合理地持续躲避。将“弹丸与射击”场景裁到唯一正常活动的钉枪，玩家在 `(13,9)`、钉枪在 `(7,9)`，无墙、道具或其他敌人；没有改成恢复占位。

[确定性复现命令](<../../prototype/enemy-behavior/inspection/reproduce-single-shooter.cjs>)在真实 `observe → decide → step` 入口执行。修复前一秒阶段策略选择 `current` 停留；tick 36 后向远离敌人的方向移动，四秒实际伤害 0、击杀 0，最终距离约 13.26。相同首次观察已有四个预测零受击、可明显接近的候选，因此不是“没有安全接敌动作”。修复前记录保留在 [红复现](<../../prototype/enemy-behavior/inspection/single-shooter-before.json>)，有匹配源码指纹。

检查的三个假设：①输出窗口内全零，连续性把停留 / 逃跑延续；②安全预测过度淘汰接近动作；③缺少候选或导航方向错误。公开候选排除了②③在该起点的解释；单变量试验只改零输出平局的接敌排序，不改世界或威胁规则，即能恢复无伤击杀，支持①。

### 局部修复

[规划器](<../../prototype/enemy-behavior/fairy-planner.prototype.js>)仍先筛最低累计预测受击，再筛最高输出积分。仅当剩余候选的最好输出 `≤1e-6`，且存在 `>1e-6` 的正向接敌进展时，才在道具 / 连续性之前比较接敌进展。

```text
环带间距 = min(各存活敌人 max(0, abs(玩家到敌人距离 - 刀环半径) - 敌人半径))
接敌进展 = 当前观察环带间距 - 同候选预测终点环带间距
```

这不是“越靠近敌人中心越好”：目标是飞刀有效命中环带。只扫描已有观察与候选私有预测终点，不增加候选、不额外推进世界、不读取隐藏状态；非零输出仍按原积分排序。无敌人时起终间距都为 0，道具层不受接敌指标影响。翻向仍独立。

没有降低远程单位的威胁权重、忽略弹丸或预支击杀安全收益。首次正对钉枪的 `dir:08` / `enemy:1` 预测受击 9，仍被排除；选择零伤的斜向 `dir:07`，接敌进展约 3.137。

## 9. 全局受伤反应与两种远程身体接触（2026-10-31）

### 用户规则与实验取值

本轮用户确认：钉枪和坠物身体触碰伊埃斯后，伊埃斯扣血并朝边上震开，随后短暂无敌 **0.5–1 秒**；远程实体在接触后继续存活。用户进一步确认该受伤机制全局复用：**近战 / 远程身体接触、弹丸、落区所有有效受击统一扣血、震开并获得保护**。来源伤害值及敌人后续行为独立，手动调试与 Fairy 代行共用这条世界规则。

[一手来源核查](<fairy-contact-source-audit.md>)区分旧设计、C#、原 EnemyLab 与本轮要求。旧规格没有相应身体伤害 / 震开实现，且旧 AI 规格含“不允许无敌帧”字样；本轮将新保护作为伊埃斯共用世界规则，只验证隔离原型，正式规格与 C# 保持原样。

| 项目 | 本轮可运行语义 | 来源 |
| --- | --- | --- |
| 类型 | 钉枪 `shooter`、坠物 `dropper` 的身体投影 | 用户本轮确认；空中导航不推导身体豁免 |
| 身体伤害 | 两类型各 **4 HP**；敌人 HP 不因身体事件减少，仍可被飞刀击杀 | 研究实验值，用户尚未定量 |
| 保护 | 所有来源的有效受击后 **45 tick / 0.75 秒**，期间所有伤害共用门控；失败受击不扣血、不再震开、不续期 | 全局复用由用户确认，时长取范围内实验值 |
| 保护结束 | 若仍相交，允许下一次身体受击；已经离开则不凭空扣血 | 避免逐 tick 连续完整扣血 |
| 震开 | 身体沿接触时刻向外法线，弹丸沿飞行方向，落区从矩形中心向外；至多 **0.8 单位**，零向量确定性回退 | 研究实验值，方向与幅度待体验 |
| 位移时序 | tick 末一次 `clipped` 带体积墙扫掠；位移可被墙 / 边界缩短，速度归零，不沿震开额外判刀 | 实验离散化，不是连续冲量物理 |

具体规则只在[共享构建器](<../../prototype/enemy-behavior/build-fairy-response.prototype.cjs>)实现：`damage(s, amount, source, direction)` 统一处理伤害门控、HP / 累计记录、保护期限与待执行震开，来源只提供伤害量和方向，不重复维护保护逻辑；帧末共用一次位移执行。`observe` 公开绝对 `invulnerableUntil`，`fromObservation` 保留其截止时刻，不重新给满保护。预测仍禁飞刀伤害，不预支击杀安全。规划器、候选数、安全 / 输出窗口、接敌排序、导航与独立翻向均未修改。

沿用现有 tick 阶段顺序：身体 / 刀尖的相对扫掠事件先按时间排序，同刻身体优先；随后弹丸、落区，最后震开与拾取。**这不是所有伤害来源统一的亚帧事件求解器**；本轮没有为了局部接触规则引入新的物理系统。震开沿途不额外拾取，落点继续使用原有拾取规则。
