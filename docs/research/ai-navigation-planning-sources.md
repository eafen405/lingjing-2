# 敌人导航与 Fairy 四秒代行：一手来源核查

> 日期：2026-10-30。范围：本项目内置敌人导航与玩家同构的 Fairy 代行；仅提供资料与设计推论，不修改实现或正式规格。
> 方法限制：已调用 `web_search`，但搜索插件返回 401；随后以 `web_fetch` 直接核读以下作者页、论文摘要、官方文档与公开源码。PDF 抓取器不支持的正文未冒充通读；未运行命令、测试或性能测量。
> 标记：**来源**＝外部资料明确陈述；**代码事实**＝当前仓库所见；**推论/建议**＝针对本项目的判断，不是来源作者对本游戏的背书。所有本地链接从本报告目录解析。

## 1. 当前项目边界

- **规格要求**：共享网格、追兵流场、定点 A*、100ms 重规划、1s 前瞻及 P0–P3；文档状态仍为待确认，不能等同于已实现。[AI 规格](<../specs/ai.md#L3-L22>)
- **代码事实**：当前 `BaselinePlanner` 是 16 方向贪心基线，只按方向外推一个端点并评分；没有完整轨迹推进、候选目标点集合或 P0–P3。[基线规划器](<../../prototype/battlesim/src/Fairy/BaselinePlanner.cs#L6-L81>)
- **代码事实**：玩家速度上限为 4、加速度为 60；执行先限幅输入，再逐 tick 逼近目标速度、积分并解墙碰撞，不能把输入方向当成立刻获得的速度。[玩家](<../../prototype/battlesim/src/Combat/Player.cs#L8-L23>)、[执行层](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L164-L183>)
- **代码事实**：固定模拟 60Hz、决策每 6 tick、流场每 15 tick、代行 240 tick；A* 每 tick 最多发起 4 次，超额本原型是下次再试，并非已经有排队器。[节拍与配额](<../../prototype/battlesim/src/Core/SimConstants.cs#L8-L29>)
- **代码事实**：快照含玩家速度、敌人种类/位置/状态，却不含敌人速度、状态已过 tick 或冲锋锁定方向；不能直接宣称已有精确敌人预测所需的全部信息。[快照](<../../prototype/battlesim/src/Fairy/IPlanner.cs#L32-L92>)、[撞针状态](<../../prototype/battlesim/src/Enemies/Striker.cs#L31-L34>)、[敌人状态时间](<../../prototype/battlesim/src/Enemies/Enemy.cs#L24-L38>)
- **边界**：Boss、拾取等仍有占位；本报告不把论文算法、建议或主实验中的隔离探针写成正式能力。[原型边界](<../../prototype/battlesim/README.md#L111-L114>)

## 2. 一手来源表

| 编号 | 已核读来源与位置 | 能支持什么；不能外推什么 |
| --- | --- | --- |
| S1 | LaValle《Planning Algorithms》§8.2.3，[目标反向波前][S1] | 从目标做 Dijkstra 可计算离散导航函数；单位边权时可退化为 BFS 波前。 |
| S2 | Sedgewick/Wayne 官方实现，[DijkstraSP][S2] | 非负边权、`edge weight + dist` 松弛、二叉堆复杂度；不是本项目真机基准。 |
| S3 | Harabor/Grastien 2011，[AAAI 原论文摘要][S3]；[作者项目页][S3a] | JPS 针对 uniform-cost grid，跳过中间节点，论文证明其适用模型的最优性；提速倍数是其基准结果。 |
| S4 | Recast/Detour，[官方文档][S4] | NavMesh 烘焙、运行时路径查询、分块与 Crowd 分工；分块方案复杂度更高。 |
| S5 | Fox/Burgard/Thrun 1997，[DWA 作者摘要][S5] | 短时间可达速度窗口、可安全停车的 admissible velocities；不是任意动态伤害场景的无伤定理。 |
| S6 | Nav2，[标准轨迹生成源码][S6]、[限加速度窗口源码][S6a] | 从当前速度推进、区分采样可达时间与预测时长；其机器人模型不是本游戏模型。 |
| S7 | Nav2，[DWB 主循环与评分源码][S7] | 遍历生成的候选；因后续成本非负才可在已劣于 incumbent 时短路。 |
| S8 | Nav2，[障碍 critic][S8]、[足迹 critic][S8a] | 对轨迹采样姿态检查障碍/足迹，碰撞可以直接判为非法；不能据此保证采样间安全。 |
| S9 | LaValle §5.3.4，[路径段检查][S9] | 步长过大会漏掉薄障碍；几何间隙与位移上界能为检查分辨率提供依据。 |
| S10 | LaValle §5.4.3，[局部极小与逃逸][S10]；Nav2 [振荡 critic][S10a] | 局部代价可能陷阱、频繁反向需要记忆；并未证明短时域规划全局完备。 |
| S11 | LaValle §14.1.3.2，[不可避免碰撞区域][S11] | 当前没碰撞不代表之后可避免；动量、停车距离和状态可行性很重要。 |
| S12 | Gurobi，[层级/字典序目标][S12] | 低优先级只能在高优先级允许的退化范围内优化；无需因此引入求解器。 |
| S13 | Gurobi，[确定性官方说明][S13] | 墙钟限制随机器负载变化，固定工作量限制可作为确定性替代；输入顺序同样重要。 |
| S14 | Erin Catto，[Box2D 确定性说明][S14] | 集合/并行完成顺序、编译与浮点设置可能破坏复现；固定种子不是充分条件。 |

## 3. 静态小网格、40 敌与升级条件

- **来源**：从目标反向求代价到达函数，可为各起点提供反馈导航；非负加权图的 Dijkstra 二叉堆实现为 `O(E log V)`，不要求每个追兵单独搜索。[S1] [S2]
- **推论**：现有场景的 40×24 只有 960 格；8 邻接时边数至多约 `8V`。一次共享流场加每敌一次查表，是 40 个同目标追兵合理的首选结构；这只说明规模匹配，不证明任意设备达到 2ms。[场景](<../../prototype/battlesim/scenarios/corridor_pressure.json#L7-L15>)、[流场](<../../prototype/battlesim/src/Nav/FlowField.cs#L42-L107>)、[S2]
- **代码事实/推论**：当前边权是 1 与 √2，不能不改变最短路含义就换成普通 BFS；A* 与流场共用固定邻居次序，且要求两个正交邻格都可走才允许对角。[A* 邻接](<../../prototype/battlesim/src/Nav/AStar.cs#L97-L128>)、[流场邻接](<../../prototype/battlesim/src/Nav/FlowField.cs#L76-L105>)、[S1]
- **必要区分**：距离场正确，不代表读取它的后继策略必然是加权最短路。应选择 `argmin_n(edge(c,n) + dist[n])`，或保存松弛时的前驱；只取最小 `dist[n]` 只能说明下降，不足以证明 Bellman 最优。[S2]
- **代码事实**：现有流场后处理确实比较 `_dist[ni] < best`，未比较边权加邻点距离。**建议**先核对这个图后继语义，再讨论换 JPS；本报告没有修改或运行该实现。[梯度选择](<../../prototype/battlesim/src/Nav/FlowField.cs#L109-L147>)、[S2]
- **推论**：流场服务共目标追兵；少数不同目标、保持射程或绕到指定侧的单位仍用 A*。地图/通行规则变更使派生场失效，目标换格可触发更新；静态图并不等于移动目标无需重算。[现有导航分工](<../specs/ai.md#L52-L71>)、[S1]

| 选择 | 适用条件与收益 | 本项目判断 |
| --- | --- | --- |
| 共享 Dijkstra + A* | 静态小图、正边权、多数追兵同目标；共用一次全图结果。[S1] [S2] | **先保留**；分别记录重算、搜索、跟随和分离成本，而非把敌人数直接当搜索次数。 |
| JPS | 仍是符合其假设的规则网格，长距离单对点 A* 的扩展已成为实测瓶颈。[S3] | **暂缓**；先核对对角禁角策略、半径与代价模型，不把论文倍数套到 960 格上。 |
| NavMesh/Detour | 任意关卡几何、三角面/多边形表达或更大场景确有需要。[S4] | **暂缓**；当前墙格图已可复用，没有证据表明另建烘焙/查询权威更小。 |
| 分块 NavMesh/Crowd | 需要局部重烘焙、流式场景或独立人群移动功能。[S4] | **不因 40 敌直接引入**；Crowd 与网格寻路不是同一层，也不代替战斗伤害预测。 |

## 4. DWA 思路：评估真正能执行的短轨迹

- **来源**：DWA 搜索的是短时间内可达的速度，并先要求沿该运动能够安全停车；不是“挑一个不在墙里的目标点，再立即以满速朝它走”。[S5]
- **来源/迁移边界**：Nav2 将窗口的加速时间与轨迹的模拟时长分开，并可逐段用加减速度推进；本游戏没有车头约束，不应照搬 `(v, ω)` 机器人圆弧，而应复用自己的二维运动内核。[S6] [S6a]、[运动内核](<../../prototype/battlesim/src/Core/Motion.cs#L13-L26>)
- **推论**：若用可达速度采样，需满足速度上限与 `||v_next − v_now|| ≤ a·Δt`；若用目标点/方向采样，则必须从当前速度通过同一执行模型 rollout，不能把尚未达到的目标速度当作实际速度。[S5] [S6]、[真实积分](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L174-L183>)
- **推论**：候选应包含继续当前控制、减速/停止、可达绕行和沿全局路径推进等分支；“停止输入”仍有制动位移，不是特殊瞬停能力。[玩家积分](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L174-L183>)、[S5]
- **来源/推论**：连续恒减速度近似有 `t_stop=v/a`、`d_stop=v²/(2a)`；它仅供量级检查。此处离散积分和墙解算会改变精确结果，实际判定宜逐 tick 模拟制动尾段，并覆盖下一次决策前的反应位移。[S11]、[运动实现](<../../prototype/battlesim/src/Core/Motion.cs#L15-L26>)
- **建议**：区分控制承诺期（当前每 6 tick）、预测时域（规格 1s）与制动尾段；每次只执行下一决策间隔的前缀。规格“100ms 重评”与“执行前 200ms”须先统一语义，不能默默把 200ms 当不可打断指令。[规格时域](<../specs/ai.md#L76-L95>)、[当前节拍](<../../prototype/battlesim/src/Core/SimConstants.cs#L13-L17>)
- **来源/推论**：仅验证端点或每 0.1s 的离散位置，可能漏过中间碰撞；最小方案是按真实 60Hz 规则核算伤害/碰撞，另把连续扫掠或更保守位移界作为可选加强，且不得宣称 60Hz 本身已给连续保证。[S8] [S9]、[当前伤害时序](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L88-L122>)
- **代码事实/建议**：A* 拉直使用 clearance 0.3，而玩家半径 0.4；网格可达、拉直可通与角色实际能过不是同一证明。优先统一半径/通行语义并核对路径段，再加更复杂局部规划。[拉直](<../../prototype/battlesim/src/Nav/AStar.cs#L149-L180>)、[玩家半径](<../../prototype/battlesim/src/Combat/Player.cs#L8-L14>)、[S9]

### 短前瞻与局部陷阱

- **来源**：局部代价下降可能停在局部极小；Nav2 的振荡 critic 保留指令反向历史，并按位移/角度/时间重置限制。这说明有状态防抖是实际工程问题，不是全局到达保证。[S10] [S10a]
- **推论**：U 形墙、袋形通道、先远离目标才绕得开的障碍，以及短时安全却越走越窄的动态包围，都可能让短前瞻或端点评分错误；增加几个方向不能证明消除陷阱。[S10] [S11]
- **最小建议**：保留全局 A*/流场引导，以路径进展/代价到达衡量绕行；连续低进展时稳定切换绕行候选，安全层允许时保留上一有效路线，不能用防抖阻止紧急避险。[现有路径跟随](<../../prototype/battlesim/src/Nav/PathFollower.cs#L20-L59>)、[S10] [S10a]
- **边界**：全局路径只解决静态拓扑；停车也未必能避开冲锋、弹丸或延迟落区。不得把 DWA 的停车可行性偷换成游戏四秒无伤。[S5] [S11]、[伤害来源](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L306-L393>)

## 5. 全候选精评与粗筛精评

- **来源**：DWB 主循环遍历生成器提供的全部速度候选；非法轨迹可被拒绝，评分可提前短路。这里的“全部”仍只是被采样出来的有限集合，不是连续控制空间的全局优化。[S7]
- **建议**：先对稳定生成并封顶的 12–20 个候选、两个旋转方向使用同一精评模型，作为之后优化的参考；候选生成/封顶本身仍会漏解，不能把“全候选”写成全局最优。[规格候选数](<../specs/ai.md#L82-L106>)、[S7]
- **推论算量**：若 1s 按 60Hz、40 敌、两旋转方向独立推进，则仅敌人状态推进约为 `C×2×60×40`，即每次决策 57,600–96,000 次；这不是 CPU 指令数、耗时或真机结论，尚不含寻路/弹丸/落区。[规格时域](<../specs/ai.md#L91-L99>)、[当前步长](<../../prototype/battlesim/src/Core/SimConstants.cs#L8-L14>)
- **有损粗筛**：先按端点距离/简化伤害选 top-k，再精评，可能产生“危险候选被乐观保留”与“唯一安全/可绕行候选被误删”两类风险；只重评赢家能纠正前者，却无法恢复后者。此为有限候选集合被删减的逻辑风险，不是来源给出的误差上界。[S7] [S9]
- **可证明短路**：若最小化的累计损失只会增加，已超过 incumbent 或硬阈值即可中止；DWB 明确以“后续都加正值”为依据。换成含负奖励的总分、不同优先级或未来可抵消损失时，不可照搬。[S7]
- **安全筛除边界**：可用已证明的不可达/必碰撞证据淘汰；只有下界已超过阈值才能据此判危险。粗略预测“尚未见到伤害”不是安全上界，不足以给候选贴安全标签。[S9] [S11]
- **建议**：先复用快照只读数据、缓存与有界短路；若测量后确需 top-k，保持参考全评并对同一快照比较安全漏召回、选择分歧与分层损失，不只比较最终平均分。记录粗筛被删原因，且明确退化为近似策略。[S7] [S12]
- **共享推进条件**：两旋转方向仅在不会改变敌人死亡、攻击/碰撞和后续行为时才可共享同一敌人预测；当前刀刃命中能杀敌，因此不能无条件共享所有战斗推进。[刀刃结算](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L185-L244>)

## 6. 字典序安全筛选，以及“预测零伤害”的边界

- **来源**：字典序按优先级约束后续优化，权重和则允许指标交换；允许多少高层退化必须显式定义。这里借用的是语义，不建议引入 Gurobi 依赖。[S12]
- **规格事实**：P0 当前是 `D≤2% maxHP`，P1 是保留最优覆盖的 85%，再评 P2/P3；这应称“带阈值/容差的层级筛选”，不是严格逐项最优，也不是无伤筛选。[P0–P3](<../specs/ai.md#L101-L108>)、[S12]
- **推论**：安全集中即使有预测 0 伤害候选，规格仍可能为覆盖/输出选预测微伤候选；因此“可存活黄金场景必须零掉血”的验收与“P0 允许微伤”的策略目标须分别表述、核对。[安全规则](<../specs/ai.md#L101-L106>)、[验收](<../specs/ai.md#L165-L169>)
- **建议流程**：先剔除动作/路径不可执行者，再计算预测损失与危险裕量，明确 P0 可接受集合；只在集合内做覆盖、相对速度与道具排序。硬碰撞/动作约束不允许由输出收益抵消。[S5] [S8] [S12]
- **预测零伤害≠无伤保证**：有限时域之外的威胁、采样间漏判、缺失状态、模型误差、执行偏差及不可见事件均不在单次 `D=0` 结论内；四秒中反复做一秒预测并不自动构成四秒证明。[S9] [S11]、[快照边界](<../../prototype/battlesim/src/Fairy/IPlanner.cs#L56-L92>)
- **信息边界建议**：预测只使用玩家可观察状态及合法历史推断；若状态剩余时间/锁定方向无法观察，就保守估计或承认不确定，不读取未来刷新脚本、未来 PRNG 或隐藏状态来制造无伤结果。[同构信息约束](<../specs/ai.md#L183-L185>)
- **术语建议**：确定性简化 rollout 的输出称“模型预测损失”较准确；未定义概率分布或校准误差时，不将其解释成真实统计期望或可信概率保证。[规格 D 定义](<../specs/ai.md#L95-L99>)、[S11]
- **兜底边界**：可接受集合为空时报告最小预测损失/不可行原因，按已定义规则撤退或制动；“反向逃离最近敌人”与“停止”也需检查墙、动量和其他威胁，不能保证总能找到无伤动作。[规格兜底](<../specs/ai.md#L115-L120>)、[S5] [S11]

## 7. 可复现决策：固定工作量而非墙钟截断

- **来源**：Gurobi 官方区分墙钟 `TimeLimit` 与确定性 `WorkLimit`；同输入还包括参数、变量/约束顺序。Box2D 作者也指出跨线程完成顺序和浮点设置会改变结果。[S13] [S14]
- **建议**：固定候选上限、方向次序、rollout tick 数、A* 展开数与请求顺序；预算不足时按固定次序结束并给出明确状态，不用“计时超过 2ms 就停止搜索”参与选招。[S13]、[现有 A* 展开上限](<../../prototype/battlesim/src/Nav/AStar.cs#L38-L91>)
- **代码事实/建议**：A* 和流场堆已按 `(key,nodeId)` 决胜；新候选用稳定 ID 与固定全序，过滤后仍保留 ID，避免容器顺序、线程先后或随机消费次序改变平局结果。[A* 平局](<../../prototype/battlesim/src/Nav/AStar.cs#L255-L257>)、[流场平局](<../../prototype/battlesim/src/Nav/FlowField.cs#L233-L234>)、[S14]
- **建议**：明确定义数值比较与容差；若需要容差桶，先确定量化规则，再按离散桶与 ID 排序，不把可能不传递的成对 epsilon“相等”直接当排序比较器。配置与量化改变也属于决策版本改变。[S13] [S14]
- **代码事实**：现有 `TimeDecision` 只包脚本/规划器调用，流场、敌人更新和分离在其它步骤；当前决策耗时指标不能冒充整帧 AI 总成本，更不能从开发机机械乘系数得出手机 2ms。[计时范围](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L126-L144>)、[帧内其它工作](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L88-L122>)
- **建议**：耗时只作观测；设备、构建配置、场景版本、峰值/分位数和分项成本应一起记录。固定工作量保证的是决策截断可复现，不保证每台机器耗时相同。[S13]
- **复现边界**：沿用逐 tick 指令与哈希，但还应标记规划器/参数版本、候选顺序、预算和 PRNG 状态；同机日志一致不证明跨平台位级一致，浮点量化哈希也不等于所有内部状态完全相同。[现有协议](<../../prototype/battlesim/README.md#L54-L61>)、[S14]

## 8. 当前最小推荐与暂不引入的复杂度

1. **保留单一图权威**：复用网格、流场和 A*；优先核对 Bellman 后继、禁角、角色半径与拉直一致性，再谈替换算法。[现有图](<../../prototype/battlesim/src/Nav/Grid.cs#L53-L82>)、[S1] [S2] [S9]
2. **先有可执行参考规划器**：在既有只读快照→同构命令接缝内，以固定候选和真实运动/伤害时序做全评；只补合法预测所必需的信息，不另建一套权威战斗规则。[接缝](<../../prototype/battlesim/src/Fairy/IPlanner.cs#L6-L29>)、[S5] [S6]
3. **安全与性能分别验收**：按真实规则检查四秒存活/掉血，另看有限模型的安全漏判与选择分歧；用固定工作预算控规模，用实机测量检验耗时，不把两者混为证明。[验收目标](<../specs/ai.md#L165-L171>)、[S9] [S13]
4. **暂不引入** JPS、NavMesh/Crowd、通用非线性 MPC、全局时空多智能体联合搜索或并行抢先返回；前两者需要对应地图/瓶颈证据，后几者不是当前窄接缝的最小补缺，并会增加模型、状态或复现成本。[S3] [S4] [S6] [S14]
5. **后续决策门槛**：只有在同场景参考全评暴露明确质量/耗时问题后，再选增加候选、延长前瞻、可证明短路或有损粗筛；每次写清解决哪个已观察失败，不把本报告直接升级为正式规格。[复杂度原则](<../../AGENTS.md#L5-L11>)、[S7] [S13]
