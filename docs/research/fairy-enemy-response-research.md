# Fairy 应对弹丸、冲锋、空降与 Boss 召唤：算法研究

> 日期：2026-10-30。状态：源码核查与方法建议。后续已复用 EnemyLab 开展隔离模拟，实际结果与限制见 [Fairy 模拟实验](<fairy-simulation-findings.md>)；未修改正式战斗实现或正式规格。
> 用户确认、代码事实、外部来源事实与本项目建议分别标注。

## 1. 已确认的目标

**用户确认：**Fairy 重点躲避远程、冲锋与空降攻击；在不扣血的边界内，让飞刀打出尽可能高的 DPS，下一级是顺便拾取道具。避免过度保守，不要求每次实际执行都完美。切换飞刀方向是独立因素，不影响 Fairy 寻路。

**用户给定输出模型：**DPS 正比于各敌人与飞刀相对速度的贡献之和。落地时只对可被飞刀有效命中的敌人累计，沿候选轨迹对时间积分或取平均，避免只看终点与瞬时峰值。

```text
P0：满足动作、通行与预测不受伤约束
P1：在可行集合内最大化飞刀 DPS
P2：输出相当时顺路拾取道具
独立控制：翻向，不改写移动目标或路线
```

**本项目建议：**安全条件满足后，直接比较输出，而不是继续优先增大离敌距离或安全余量。安全是基于当前可观察信息和有限预测模型的决策目标，不是对实际四秒必定无伤的保证；可行集合为空时，以最小预测损失作为兜底候选。这一兜底仍需验证，不把受伤本身作为单场失败条件。

**敌人输入：**尾灯与撞针接触玩家立即扣血并自毁；Boss 在自身周围生成新的小怪对象，轰炸是另一套攻击机制。现有敌人寻路作为工作起点。Boss 接触行为、召唤距离/数量/时序及具体伤害参数仍需核对。

**文档地位：**既有设计与待确认规格是核对入口；本轮按上述最新目标研究，不自动采用其 2% 微伤阈值或每场无伤验收。来源：[设计](<../design/game-design.md#L72-L87>)、[规格状态](<../specs/ai.md#L1-L6>)、[旧阈值](<../specs/ai.md#L101-L108>)、[旧验收](<../specs/ai.md#L165-L171>)。

## 2. 已有实现与证据

- **代码事实：**`BaselinePlanner` 是 16 方向、0.25 秒端点评分的占位策略，主要按敌人距离评分，不是完整的一秒时序预测。来源：[基线](<../../prototype/battlesim/src/Fairy/BaselinePlanner.cs#L6-L24>)、[评分](<../../prototype/battlesim/src/Fairy/BaselinePlanner.cs#L38-L81>)。
- **代码事实：**旧探索曾联合评价 18 个移动候选与两旋向；敌人预测把预警/恢复等状态按静止外推，没有预测阶段转换；晚于前瞻时域的落区被跳过。来源：[旧候选](<../../prototype/ai-exploration/ExplorationPlanner.cs#L48-L127>)、[预测](<../../prototype/ai-exploration/ExplorationPlanner.cs#L145-L169>)、[落区](<../../prototype/ai-exploration/ExplorationPlanner.cs#L192-L198>)。
- **旧实验观察：**曾出现 tick 234 预测损失为零、tick 240 实际损失 15 的混战反例；尚未单因素验证全部损失原因。来源：[观察与限制](<ai-exploration-findings.md#L82-L88>)。
- **代码事实：**当前 JS 敌人原型有无 DOM 的 `EnemyLab.step/reduce`，但仍未对齐接触自毁，没有敌人 HP、玩家刀刃伤害或 Boss；C# Boss 的召唤也仅为 TODO。来源：[JS 模型](<../../prototype/enemy-behavior/enemy-behavior.prototype.html#L102-L151>)、[范围](<../../prototype/enemy-behavior/README.md#L81-L88>)、[Boss 占位](<../../prototype/battlesim/src/Enemies/ChainBoss.cs#L7-L58>)。

旧实验不能作为新敌人机制下的表现结论。要评价实际 DPS、击杀与拾取收益，必须先接一致的真实结算；覆盖/相对速度代理与逐刀有限窗口命中应分别记录，不在本轮另定伤害公式。来源：[旧代理检验](<ai-exploration-findings.md#L90-L100>)。

## 3. 推荐算法：状态感知的采样式滚动规划

**本项目建议：**保留现有共享图、流场与 A*；在其上生成有限条可执行的移动轨迹，先做安全筛选，再按输出与拾取排序，只执行短前缀并持续重评。这是采样式滚动时域搜索，可称轻量 MPC 思路。

```text
合法观察 → 移动候选 → 真实运动学与攻击时序预测
         → 预测安全集合 → DPS 最大 → 拾取决胜 → 执行短前缀
翻向控制：读取观察与已选运动，独立输出旋向，不回写移动规划结果
```

先固定约 100ms 决策间隔、一秒近场前瞻和有界移动候选，便于单独比较预测模型；这些是实验配置，不是实测最优参数。不把移动候选扩成“路线 × 翻向”的联合选路。可复用既有命令中的移动和旋向字段，在内部按两个独立步骤计算，无需新增框架。来源：[命令接缝](<../../prototype/battlesim/src/Fairy/IPlanner.cs#L6-L29>)。

**评价口径需明确：**相对速度数值会受旋向影响，因此移动侧应固定其输出代理的评价约定，再独立评价翻向；不能一边要求翻向不影响路线，一边无说明地用两旋向的联合最优分数重排路线。此处分层实现不等于宣称两因素数学上完全无关，也不宣称获得联合全局最优。

玩家加速、体积、墙体约束与伤害时序复用当前世界规则；JS 与旧 C# 的运动参数不同，不能混用。来源：[JS 参数](<../../prototype/enemy-behavior/enemy-behavior.prototype.html#L42-L45>)、[JS 运动](<../../prototype/enemy-behavior/enemy-behavior.prototype.html#L85-L87>)、[C# 运动](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L174-L182>)。

**来源事实：**DWA 在短时间可达速度集合内搜索并检查机器人能否安全停车，支持评价真正可执行轨迹的思路；不证明本游戏无伤，也不要求照搬机器人的平移/角速度控制形式。来源：[Fox、Burgard、Thrun 作者摘要](<https://www.cs.cmu.edu/~dfox/abstracts/colli-ieee.abstract.html>)。

## 4. 各威胁与进攻窗口

| 威胁 | 本项目建议 |
| --- | --- |
| 钉枪与弹丸 | 按双方运动段与墙体遮挡判断会不会命中；尚在瞄准时预测继续跟踪。不因看见远程敌人就统一远离。 |
| 冲锋 | 预测预警结束、锁定、直线推进与撞墙停止；既定动作后的可利用窗口进入输出评价。 |
| 空降与轰炸 | 使用公开矩形和生效时刻；允许利用生效前的输出窗口，但需预留实际离场时间。对一秒外的已知落区保留退出期限。 |
| 接触自毁近战 | 双方运动段接触时一次伤害并移除实体，不能只在撞针冲刺期判危险。 |
| Boss 召唤 | 新小怪进入下一次当前敌人观察，沿用各自行为；与轰炸的区域/计时分别处理。 |

追击与跟踪反应依赖玩家候选运动，应在相应候选下推进，不能无条件共享同一条敌人未来轨迹。退出耗时考虑体积、加减速与可达路线，静态距离/速度不是动态安全证明。这些是待验证方案。当前模型规则来源：[敌人更新](<../../prototype/enemy-behavior/enemy-behavior.prototype.html#L94-L130>)。

**代码事实：**旧规划器已逐轮遍历当前敌人快照，新对象可以自然进入下一轮；当前 JS 也展示方向、落区倒计时和阶段剩余时间。来源：[快照遍历](<../../prototype/ai-exploration/ExplorationPlanner.cs#L145-L148>)、[可见信号](<../../prototype/enemy-behavior/enemy-behavior.prototype.html#L163-L182>)。

**本项目建议：**复用这一更新方式，更新动态威胁与轨迹评价，保留仍有效的静态几何路径。实体用独立稳定 ID，避免继承旧怪的观测历史；C# 已有单调 ID 惯例。来源：[生成](<../../prototype/battlesim/src/Sim/BattleSimulation.cs#L472-L483>)。正式表现若不展示精确阶段时间，则由合法历史估计区间；不读取未来刷新、未来随机数或隐藏目标。未知事件与已知攻击的预测错误分别记录。

## 5. 是否需要机器学习

**当前研究建议：不必先引入。**目标已经可以表达为“安全可行集内最大化输出，再顺路拾取”，优先验证预测、候选覆盖与排序是否足够。避免过度保守应先靠实际攻击时序与可行集内的输出优化，而非持续奖励远离敌人。

**来源事实：**Unity ML-Agents 的 RL（如 PPO/SAC）学习观察到动作的策略并优化未来奖励；BC/GAIL 可从示范学习。开发者仍需定义观察、动作、奖励或提供示范。训练需要已准备好的学习环境、训练器和配置。来源：[官方概览及模仿学习](<https://unity-technologies.github.io/ml-agents/ML-Agents-Overview/>)、[官方训练文档](<https://unity-technologies.github.io/ml-agents/Training-ML-Agents/>)。

**后续条件：**实际出现采样规划难以解决的行为瓶颈，且有可复用、结算一致的训练环境时，再比较 RL；有覆盖目标情境且风格合意的示范时，再比较模仿学习。无模型 RL 不依赖手写规划用的前向模型，但仍依赖可信的可交互环境，也不自动保证硬安全条件。现有规格将 ML 列在范围外，引入属于待讨论变更。来源：[范围](<../specs/ai.md#L175-L180>)。本轮未训练或测量样本量、效果、设备性能。

## 6. 方法选择与最小实验

- **现有 A*/流场：**继续处理绕障，不承担全部攻击时序评价。
- **势场/即时转向：**可作简单对照；局部陷阱与短时域限制见[既有核查](<ai-navigation-planning-sources.md#L62-L67>)。
- **ORCA：**作者的对等避碰充分条件让双方各承担一半责任，不能直接继承给以攻击为目的的敌人；它也不是本项目 DPS/落区计时评价器。来源：[作者页](<https://gamma-web.iacs.umd.edu/ORCA/>)。
- **状态机、行为树、GOAP：**可组织意图，但本轮无需为此另建框架；仍需可执行轨迹评价。
- **MCTS：**先解决已有预测失配；出现固定动作集合必须转弯的具体反例后，再比较有界动作序列搜索。

建议顺序：

1. 在当前 JS 世界复用导航与运动，落实接触自毁等已确认规则，核对数值与时序；不同时迁移三套实现。
2. 固定移动候选、旋向条件、种子、决策间隔和安全/DPS规则，仅对比恒速/静止外推与攻击阶段预测；覆盖远程、冲锋、落区。
3. 独立接入 Boss 周边召唤与轰炸；所有对照组看到同样的新实体，不故意漏怪。
4. 真实刀刃/HP/击杀接入后，评价安全可行集内的 DPS 排序与拾取；单独验证翻向控制不修改移动规划结果。
5. 记录四秒掉血、存活、实际输出、攻击覆盖、拾取收益、无进展时间、下一决策前的预测漏判与本机耗时。比较整秒预测时须注意之后实际控制已改变，不能直接归因于同一动作。

“尽可能最优”限于当前候选、合法信息、预测模型与计算预算。固定工作量和稳定排序用于复现；耗时不参与选招。手机 2ms、全局最优或每场无伤均没有本轮实测支持。来源：[复现与计时核查](<ai-navigation-planning-sources.md#L91-L99>)。
