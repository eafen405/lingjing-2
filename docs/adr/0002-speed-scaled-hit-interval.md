# 命中间隔与正反切冷却都按角速度定义，而不用固定帧数

> 状态：**部分已被 ADR-0004 取代**（2026-11-04 标注）：本文的「再次命中间隔 = `2π / |ω_rel|`」已废弃，改为固定「同一把刀转满一圈 `2π/ω`」，相对速度降级为伤害倍率；「正反切冷却 = `(2π / N) / ω`」仍有效。偏差见文末。

碰撞判定每 tick 都会把「刀尖是否压在以骸圆内」判一遍，所以必须有一条再次命中的间隔规则。原实现用的是固定 0.1s（6 tick），它与角速度无关，结果是一把刀在同一只以骸身上每秒命中 10 次——伤害与「相对速度」彻底脱钩，`game-design.md` §4.2 那条 `N·|ω_rel|/2π` 在运行时根本不成立。我们决定把两条间隔都交给角速度：**同一把刀对同一只以骸的再次命中间隔 = `2π / |ω_rel|`**（按命中那一刻的相对角速度算），**正反切冷却 = `(2π / N) / ω`**。前者让 §4.2 的公式成为碰撞判定的自然结果而不是另写的近似；后者把翻转的代价锚在「一把刀走过一格扇区的时间」上，否则连续翻转可以把刀停在原地、把以骸卡在刀与刀之间反复吃伤害。

## Considered Options

- **固定帧冷却（原方案，6 tick）**：实现最简单，但它把伤害与相对速度解耦，§4.2 的整条玩法前提失效。否决。
- **每刀每圈固定一次（`2π / ω`）**：满足「每把刀一圈内只命中同一以骸一次」，但仍丢掉走位加成——顺着刃口走不会更快。
- **按 `2π / |ω_rel|`（选定）**：静止时正好退化成「一圈一次」，顺扫时间隔变短、逆扫变长，`ω_rel → 0` 时间隔趋于无穷。三个行为都由一条公式给出。

## Consequences

- 静止且 4 刀、ω = 2.5 时，单只贴在环上的以骸约 1.6 次命中/秒；顺着刃口移动到 ω_rel = 4.5 时约 2.9 次/秒。伤害数值要按这个量级校，不能沿用按固定冷却调出来的数。
- 正反切的基础冷却是 0.63s，比原来的 0.1s 慢一个量级；但它随「刀数上限」与「角速度」成长而缩短，所以成长本身会让操作更跟手。
- 一圈内对同一只以骸只命中一次是按**每一把刀**算的；多只以骸同时贴在环上时，一把刀可以对它们各自命中，所以把以骸聚拢是有收益的。
- 两条规则都只读当前世界的量，仍然是确定性的，不引入墙钟时间。

## 与实现的偏差（2026-11-04）

- **命中间隔已废弃**：`2π / |ω_rel|` 不再使用。现行口径是「同一把刀对同一只以骸转满一圈（`2π/ω`）才能再次命中」，与相对速度无关（`Assets/_Project/Scripts/Combat/DamageRules.cs` 的 `BladeHitIntervalTicks`）。相对速度改为只决定伤害倍率 `clamp(ω_rel/ω, 0.8, 1.3)`（`RelativeDamageFactor`），见 ADR-0004。
- **正反切冷却仍有效**：`(2π / N) / ω` 与实现一致，见 `Assets/_Project/Scripts/Combat/BladeRing.cs` 的 `BladeGap` / `GapSeconds` / `ReverseCooldownTicks`。
- 本文正文与 Considered Options 保留原样，不改写当时的结论。
