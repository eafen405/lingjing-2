# 音频规格：Fairy 语音、音效与 BGM

> 规格状态：待确认（2026-10-30）。上游设计见 `docs/design/game-design.md` §11；任务见 `docs/plan/backlog.md` T24–T25。
> 本文只定「说什么、怎么生成、什么时候播、怎么验收」，不定具体音色设计。

## Problem Statement

设计稿只写了「Fairy 语音用 gptsovits 合成，已有权重」。具体到能开工的层面全是空的：说哪几句、什么时候说、两句撞车谁先播、用什么参数合成、输出什么格式、响度多少、字幕怎么出、音效有哪些。

不解决会出三类问题：**语义层**——战斗里语音乱插、关键提示被闲聊盖掉；**工程层**——每条都手工合成、格式不一、导入设置靠人记；**授权层**——模型来自第三方，署不署名、能不能商用、哪些模型不能用没有结论。

## Solution

三件事：

1. **台词表**：稳定 id + 触发事件 + 优先级 + 冷却 + 字幕，作为唯一权威；文案先出初稿，由作者改定。
2. **离线合成流水线**：GPT-SoVITS 本地推理，固定权重与参考音频，批量出 44.1k mono → 响度归一 → Ogg，附 `voice_manifest.json`。
3. **运行时 AudioDirector**：VO 单通道、按优先级抢占、冷却去重、BGM 闪避、字幕队列；音效走通道池。

## User Stories

1. As a 玩家，I want 每关开场听到 Fairy 介绍本关机制，so that 我知道这关要注意什么。
2. As a 玩家，I want Boss 登场时听到它的行为提示，so that 我不会被第一次冲锋打得莫名其妙。
3. As a 玩家，I want 按下技能时听到 Fairy 说「交给我」，so that 代行的开始有明确的听觉反馈。
4. As a 玩家，I want 代行结束时听到归还控制权的一句话，so that 我不会在结束瞬间还以为 AI 在操作。
5. As a 玩家，I want 血量危险时听到一次提醒，so that 我不会因为盯着敌人而忽略血条。
6. As a 玩家，I want 死亡与通关各有一句收束，so that 一局有始有终。
7. As a 玩家，I want 战斗激烈时不要被闲聊打断，so that 语音不会盖住音效和节奏。
8. As a 玩家，I want 语音播放时 BGM 自动压低，so that 我听清台词。
9. As a 玩家，I want 台词有字幕，so that 我在静音或嘈杂环境也能读懂。
10. As a 玩家，I want 首次遇到新道具/新操作时有一句提示，so that 我不用猜。
11. As a 玩家，I want 同一条提示不会反复刷屏，so that 它不会变成噪音。
12. As a 玩家，I want 命中、碎刀、拾取、预警各有清晰音效，so that 我不看画面也能判断状态。
13. As a 玩家，I want 敌人冲锋与空袭有可区分的前摇音，so that 我能靠听觉提前反应。
14. As a 音频制作者，I want 台词以 id + 文本的清单形式维护，so that 改文案只需要重跑一条命令。
15. As a 音频制作者，I want 合成参数固定并可复现，so that 同一句话两次生成不会差太多。
16. As a 音频制作者，I want 输出响度统一，so that 混音时不需要逐条手调。
17. As a 程序，I want 语音由事件触发而不是散落在各处调用，so that 加一句台词不改战斗代码。
18. As a 程序，I want 优先级与冷却由解析器统一裁决，so that 不会出现两句语音叠在一起。
19. As a 程序，I want 清单缺失时能明确报错，so that 不会在真机上才发现某句没生成。
20. As a 验收者，I want 每条语音有可听的验收标准，so that 「生成完了」不等于「能用」。
21. As a 项目维护者，I want 语音模型的来源与授权写清楚，so that 交付时不会踩版权。
22. As a 项目维护者，I want 明确哪些模型不能用，so that 不会误用受限音色。

## Implementation Decisions

### 1. 台词表（唯一权威）

每条台词是一个条目，字段固定：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定标识，`vo_fairy_<event>[_<n>]`，一旦发布不复用 |
| `text` | 朗读文本（同时作为字幕） |
| `trigger` | 触发事件，见 §2 |
| `priority` | P0–P3，见 §3 |
| `cooldown` | 同 id 最小间隔（秒），默认 30 |
| `interrupt` | 是否可被更高优先级打断，默认 true |

**文案是初稿**，作者可整句改；改文本只需重跑合成，不改 id，避免代码与资源脱钩。

另有**制作字段** `情绪`、`时长`（见 §2.1）：只服务试听勾选与合成参考，不进运行时、不进 `voice_manifest.json`。

### 2. 触发事件

| 事件 | 参数 | 说明 |
| --- | --- | --- |
| `level_start` | levelId | 关卡开场，进场后 1s 播放 |
| `boss_intro` | bossId | Boss 血条出现时 |
| `daika_start` / `daika_end` | — | 代行开始 / 结束 |
| `low_hp` | — | 血量首次低于 35%，冷却 60s |
| `player_death` | — | 死亡结算 |
| `level_clear` | levelId | 通关结算 |
| `tutorial` | key：`knife` / `heal` / `energy` / `switch` / `charge` | 首次拾取刀、血包、能量球；首次正反切；首次满充能 |
| `menu_idle` | — | 主菜单空闲 30s，且不在战斗中 |

### 2.1 台词表（v1，10 条）

> 不预估时长：合成后按 `voice_manifest.json` 的实测值验收，超 5s 的句子回头拆。

| `vo_fairy_death` | `player_death` | 结论：数据回收完毕。〔本次得分：<scores>分。〕 | 平静·冷 | P0 | 30 | 否 |
| `vo_fairy_tut_knife` | `tutorial(knife)` | 检测到飞刀损耗。 | 平静·上报 | P2 | 30 | 是 |

- **预算 10 条**：只留能改变玩家下一步动作的句子；重复解释与「屏幕已经写了」的内容一律不进语音。
- **分数只上字幕、不念**：`vo_fairy_death` 的朗读范围到「数据回收完毕。」为止，`〔〕` 里那段是纯字幕。合成脚本遇到朗读范围内的 `<变量>` 直接报错——这条是硬规则，不做例外。
- 事件覆盖：`level_start` 2、`boss_intro` 1（两个 Boss 共用，参数写 `*` 表示任意 bossId）、`daika_start` / `daika_end` 各 1、`low_hp` 1、`player_death` 1、`tutorial` 1、`menu_idle` 2。**`level_clear` 目前没有句子**，缺口见 §2.2。
- `menu_idle` 是第一个有真实变体的事件（`_2` 后缀）：`VoiceCueResolver` 随机选且不连续重复。
- 教学句按 §3 是 P2：教学发生在战斗中，P3 会被「战斗中禁播」挡掉。

### 2.2 待补事件（建议，确认后再进 §2.1）

筛的标准只有一条：**这条语音能不能改变玩家的下一步动作**。按这个标准，现在缺的是「不知道按哪个键」和「一局没有收束」两类。

#### 开头引导（第一关第一次，按条件推进，不按时间灌）

| 顺序 | 事件 | 条件 | 建议文案 |
| --- | --- | --- | --- |
| 1 | `level_start(1)` | 进场 1s | 已进入空洞入口，请主人保持移动。（已有） |
| 2 | `tutorial(move)` | 玩家移动累计满 0.6s | 飞刀就贴着主人转，碰到就切。 |
| 3 | `tutorial(skill)` | 首次充能超过 50% | 右下技能键，满槽交给我。 |
| 4 | `tutorial(switch)` | 首次被 3 只以上以骸贴身 | 上方键翻转刀刃。 |

- 只走这一遍：条件不触发就不播，玩家自己先发现了更好；不重播、不总结。
- 3 和 4 的先后由玩家行为决定（可能先被围住、后攒满充能），不强制排队。

#### 敌人与阶段

| 事件 | 条件 | 建议文案 | 理由 |
| --- | --- | --- | --- |
| `enemy_first_sight(撞针)` | 撞针首次进视野 | 撞针蓄力时，横向躲。 | 0.6s 预警后直线突刺，横向是唯一正解 |
| `enemy_first_sight(钉枪)` | 钉枪首次进视野 | 钉枪在瞄你。铆钉慢，绕开。 | 弹速慢、绕柱有效，但玩家不会自己发现 |
| `boss_phase(连环,50%)` | 连环血量首破 50% | 它开始召唤。先清钉枪。 | 阶段改变打法，一局只出现一次 |
| `boss_phase(骤雨,60%)` | 骤雨血量首破 60% | 落区变多了。 | 同上 |

#### 收束

| 事件 | 条件 | 建议文案 |
| --- | --- | --- |
| `level_clear(2)` | 第二关通关 | 全部清空。记录已归档。 |

- 第一关通关是过程节点，交给结算 UI；只有真正结束的一局需要一句。
- **不做**：三种拾取（`sfx_pickup_*` 已覆盖）、充能满（`sfx_charge_full`）、刀碎、受伤、三选一弹窗——屏幕已经说清楚，再加语音就是噪音。
- 采用任何一条都要先扩 §2 的事件表（新增 `enemy_first_sight`、`boss_phase`，以及 `tutorial` 的 `move` / `skill` 键），再进 §2.1：事件名和参数名一起定，避免代码里出现第二套事件名。

### 3. 优先级与抢占

- **P0** 死亡 / 通关 ｜ **P1** Boss / 代行 ｜ **P2** 低血 / 教学 / 关卡开场 ｜ **P3** 闲聊（只有主菜单待机）。
- 规则：高优先级**打断**低优先级（当前句 0.1s 淡出）；同级**排队**；VO 通道任意时刻只播一条。
- 战斗中禁止 P3；`menu_idle` 只在主菜单。
- 每条独立冷却，避免同一句反复触发。

### 4. 合成流水线

脚本：`tools/voice/synth.py`，用 GPT-SoVITS 自带的解释器跑：

```
D:\Agents\GPT-Sovits\GPT-SoVITS-1007-cu128\runtime\python.exe tools\voice\synth.py
```

- 环境：`D:\Agents\GPT-Sovits\GPT-SoVITS-1007-cu128`（Python 3.11、torch 2.8+cu128、RTX 5060 8GB 可用）。
- 权重：GPT `D:\Agents\Fairy\Fairy\Fairy\Fairy-e10.ckpt`；SoVITS `D:\Agents\Fairy\Fairy\Fairy\Fairy_e10_s870.pth`。
- **版本是 v2**：ckpt 里的 `pretrained_s1` 指向 `gsv-v2final-pretrained`，所以在 `TTS_Config` 里写死 `version: v2`，不读安装目录的 `weight.json`（它指向芙宁娜）。
- 参考音频：同目录下唯一那条 wav，48k mono；**参考文本 = 该 wav 的文件名**（去掉扩展名），不另维护。
- 合成参数固定：seed `20261030`、top_k 5、top_p 1.0、temperature 1.0、repetition_penalty 1.35、`text_split_method=cut5`，half 精度。

#### 4.1 分段合成与停顿（关键）

模型自己给的句读间隔偏短，且逗号与句号几乎一样长。所以**不整句合成**，而是切成短段逐段合成再拼：

| 切分标点 | 拼接静音 |
| --- | --- |
| `，` `、` | 0.40s |
| `；` | 0.45s |
| `。` `？` `！` | 0.55s |
| `（停顿）` | 0.60s |

- 每段单独送 TTS，生成后裁掉首尾静音（相对峰值 −45 dB，各留 20ms），再按上表插静音拼起来。
- 段与段之间的间隔由我们定，不由模型定；要改节奏只改这张表，不需要重训。
- 冒号**不切**：`结论：数据回收完毕。` 这种引语整体送合成，硬切会让「结论：」单独成句。
- 实测（v1）：逗号 0.44s、句号 0.59s、`（停顿）` 0.64s（含两端的 20ms 余量）。

#### 4.2 后处理与输出

- 后处理：32kHz int16 拼接 → 重采样 **44.1kHz mono** → 线性增益到 **−16 LUFS**；若峰值会超过 **−1 dBFS** 则以峰值为准（个别句子因此落在 −16.6 LUFS，属正常）。
- 编码：**Ogg Vorbis q5**。
- 输出：`vo_fairy_*.ogg` + `voice_manifest.json`（id、文件、时长、文本、触发、优先级、冷却、可否打断、朗读提示、分段、实测响度与增益）。
- 落点：`tools/voice/out/v1/`，整目录不入库（`out/.gitignore`）；是否随 APK 提交由 T25 定。
- 一条命令重建全部；`--only <id1,id2>` 单条重跑；`--dry-run` 只解析台词表并打印分段，不加载模型（改文案时先跑这个）。

### 5. 运行时

- `AudioDirector` 三通道：BGM、VO、SFX（8 个 voice 的池）。
- VO 播放时 BGM 在 0.2s 内降到 −6dB，结束后恢复。
- 字幕：底部安全区，显示 `max(1.5s, clip 时长)`；同队列排队；与语音同生命周期。
- 事件只发语义事件（`level_start`、`daika_start`…），由 `VoiceCueResolver` 选 cue；战斗代码不直接调播放。

### 9. 朗读与文案规范

#### 9.1 读音与写法

- 专有名词读音表：伊埃斯、邦布、以骸、空洞、正反切、Fairy（读英文）。合成后逐条试听，读音错误改写成谐音再合成。
- **数字一律写汉字**（`三秒`、`百分之三十五`），不写 `35%` / `1.5s`：TTS 对符号的读法不稳定。
- 标点照常用；省略号只用 `……`，破折号只用 `——`（表示被切断，只给死亡/故障类句子）。
- **三种标记，只有这三种**（其余括号、引号、嵌套引语一律不用）：
  - `〔…〕` **只进字幕、不朗读**：合成前整段剥掉，字幕去掉方括号保留内容。
  - `<name>` **运行时变量，只允许出现在 `〔〕` 里**。当前只有 `<scores>`（本局得分，字幕渲染成 `1240分`）。朗读范围内出现变量就算错，合成脚本直接报错——**分数不念**。
  - `（停顿）` 朗读标记：合成时换成 0.3s 静音，字幕不显示。
- 语气总纲：Fairy 是「冷静、略带优越感的 AI」，句子短；不卖萌、不解释设定。
- 单句以**实测**时长 1.5–5 秒为准（表里不再预估）；超 5 秒的句子拆两条。

#### 9.2 篇幅、时机与句式

**先说篇幅**——短是硬指标，不是风格偏好：

- **一条语音只回答一个问题**。默认 12 字以内，硬上限 20 字；超了先删修饰，再删整句。
- 只在两种时机开口：① 玩家不知道下一步做什么、或即将做错；② 不可逆的状态变化（死亡、通关、Boss 阶段）。
- 屏幕已经显示的事不再说：拾取成功、充能已满、刀碎了——交给音效与 UI。
- 教学只讲一次：不复述、不总结、不点评玩家的操作。

**再说话的样子**（原著里 Fairy 反复出现的骨架）：

- **先报告、再建议**：`警告，生命值过低。请脱离包围。`——前半句是检测结果，后半句是可执行动作；只报告不建议的句子只留给结算类（死亡、通关）。
- **状态词开头**：`警告，` `提示，` `检测到…` `…确认。` `…已归还。`；同意/否定用 `肯定。` `否定。`。不用「哎呀」「唔」这类语气词。
- **量化优先**：能给数字就给数字（`三秒`、`百分之三十五`），不写「很快」「有点危险」。
- **短句、少主语**：一句里最多一个「我」或称谓；省略主语是常态（原著：`检测到以太活性激增，注意规避攻击。`）。
- **全篇无感叹号**；反问句可以，一条最多一个问号，且只用来挤兑（`主人，您已经放弃思考了吗？`）。
- 优越感写在**内容**里，不写在语气里：她说的是事实与数据，只是顺带让你知道她算得比你快（`否定。这正是我的核心功能。`）。

#### 9.3 称谓

- Fairy 称伊埃斯为「主人」，与原著一致；对主人称「您」，不称「你」。
- 「主人」一句最多一次；报警句以「警告，」开头时不再叠称谓（`警告，生命值过低。`）。
- 若作者决定改称谓（例如改叫「伊埃斯」），受影响 5 条：`vo_fairy_level_start_1`、`vo_fairy_level_start_2`、`vo_fairy_daika_end`、`vo_fairy_menu_idle`、`vo_fairy_menu_idle_2`。

## Testing Decisions

- **唯一接缝**：`VoiceCueResolver`——纯 C#，输入 `(eventId, context)`，输出要播的 cue 或 null。所有优先级、冷却、战斗态禁播规则都在这里，可脱离音频测试。
- 单元测试（EditMode）：
  - 高优先级抢占低优先级、低优先级不打断高优先级；
  - 同 id 冷却期内不重复；
  - 战斗中 P3 被拒；
  - 同级排队顺序；
  - 未知事件返回 null 而不是抛异常。
- 资源校验：遍历 `voice_manifest.json`，断言每条 id 有对应 ogg、时长 > 0.5s、响度在 −16±2 LUFS（ffmpeg 脚本）。
- 导入校验：断言 VO 为 mono/Vorbis、SFX 为 Decompress On Load。
- 人工听感：每批抽 3 条，按 §9 的读音表与语气标准勾选。
- 先例：与美术规格共用 `SpriteResolver` 同级的纯 C# 接缝思路，测试放在 EditMode。

## Further Notes

- **模型未经充分测试**：作者 README 自述「模型还没测试，如果效果很差告诉我重炼」。因此第一步是**试听 3 条**再批量；效果不达标时优先换参考音频，其次换模型，最后才考虑重训。
- `weight.json` 目前指向芙宁娜（`原神-中文-芙宁娜_ZH`），与本项目无关；合成时必须显式指定 Fairy 权重，不要依赖该配置的默认值。
- 生成成本：20 条以内约 10–20 分钟（含模型加载）；批量脚本应支持断点续跑。
- 语音与字幕同源：字幕直接用 `text`，不另维护一份。例外只有 §9.1 那三种标记——`〔〕` 不朗读、`（停顿）` 不显示、`<scores>` 由运行时替换；「同源」指同一份文本，不是逐字相同。
- **分数不念的理由**：念一串四位数要 1.5 秒以上，而结算界面已经把它放大显示；语音只负责「这一局结束了」，数字交给屏幕。同一条规则适用于以后任何想往语音里塞数值的场合。
- **文案的来源与边界**：句式取自原著台词转录（本地 `绝区零-剧情合集\转录\**\Fairy台词.md`，官方版权，不入库、不进交付）；只借语法与语感，不抄句子。转录里「空洞里的大量提示话」正是 §9.2 那几条的出处——`警告，检测到…` / `请注意避让` / `建议…否则…`。
- **T24 与本文的一处偏差**：backlog 的 T24 验收要求覆盖「击杀里程碑」，但 §3 禁止战斗中播 P3，击杀又是连续事件、没有可判定的语义时机，v1 不做；真要做，得先在这份规格里定一个「里程碑」事件与它的冷却，不能只加文案。
- **文案定稿顺序**（建议）：先把 10 条通读一遍改定 → 试听 3 条（开场、代行、Boss 各一）→ 风格确认后整批合成 → 只要改字就 `--only <id>` 单条重跑，id 不变。
