# 算法规格：以骸寻路与 Fairy 自动代行

> 规格状态：待确认（2026-10-30）。上游设计见 `docs/design/game-design.md` §4.2、§4.5、§5；任务见 `docs/plan/backlog.md` T09–T11。
> 本文只定「怎么想、怎么走、怎么测」，不定动画与表现。

**本规格的目标是一个可复刻的原型，不是生产级 AI。** 同一份种子与场景文件，任何人跑两次都得到相同的决策序列与相同的指标；原型是纯 C# 无头模拟，不依赖 Unity 物理与渲染。手感打磨、美术表现、真机调优属于后续任务。

## Problem Statement

设计稿定了两件互相咬合的事：**以骸要追、要绕、要封走位**，**Fairy 要在 4 秒里接管玩家并打得像个熟练玩家**。但两者共用什么导航、各自用什么算法、Fairy 的「最优」怎么量化、怎么在手机上跑得动，全是空白。

不解决会有三种失败：以骸挤成一坨穿墙走直线；Fairy 要么原地打转、要么看起来像开挂（瞬移/无敌）；算法写成一团没法调、每次改动都靠肉眼在真机上试。

## Solution

三层，共用一套导航：

1. **导航层**：32px 网格 + 流场（追兵）+ A*（定点）+ 转向/分离。以骸与 Fairy 共用同一张可走图。
2. **以骸行为层**：每种以骸一个显式状态机，行为差异写在状态机里，寻路只是其中一步。
3. **Fairy 规划层**：每 100ms 做一次滚动时域规划——采样候选目标点，按 P0–P3 的**字典序**筛选与打分，走 A* 过去；方向切换作为离散动作一起评。

**Fairy 与玩家共用同一动作空间与数值**：只能移动与正反切，没有加速、无敌、传送、预知。

## User Stories

1. As a 玩家，I want 以骸绕着障碍物追我而不是卡在墙角，so that 地形是有意义的。
2. As a 玩家，I want 大量追击以骸不要叠成一个点，so that 我能看出场上到底有几个敌人。
3. As a 玩家，I want 撞针在冲锋前定住并给出预警，so that 我能判断往哪边躲。
4. As a 玩家，I want 撞针冲锋是直线且会被障碍挡住，so that 我能用柱子卡它。
5. As a 玩家，I want 钉枪和我保持距离并需要视野才开火，so that 绕柱子是有效战术。
6. As a 玩家，I want 钉枪被我贴近时会后退，so that 远程单位不是站桩靶子。
7. As a 玩家，I want 坠物从空中逼近并在我附近投下矩形落区，so that 我需要持续移动。
8. As a 玩家，I want 连环冲锋后有明显硬直，so that 我能抓住输出窗口。
9. As a 玩家，I want 连环召唤的钉枪有数量上限，so that 战斗不会变成无限刷怪。
10. As a 玩家，I want 骤雨的落区必有一块在我脚下、且预警 3 秒，so that 站着不动必挨打、动了就躲得开。
11. As a 玩家，I want 骤雨的技能之间有间隔，so that 我不会被两套机制同时压死。
12. As a 玩家，I want Fairy 代行时明显在「像人一样走位」，so that 我信任她而不是觉得被随机数接管。
13. As a 玩家，I want Fairy 优先保命，so that 她不会为了输出把我送进敌群。
14. As a 玩家，I want Fairy 尽量把敌人压在刀刃环上，so that 代行期间的输出明显高于我瞎走。
15. As a 玩家，I want Fairy 会主动切旋转方向，so that 代行像高手而不是只会绕圈。
16. As a 玩家，I want Fairy 顺路捡血包和刀，so that 代行不只是输出。
17. As a 开发者，I want 以骸与 Fairy 共用一张导航图，so that 不会出现「敌人能走、AI 不能走」的裂缝。
18. As a 开发者，I want 每种以骸的行为写成显式状态机，so that 调一个敌人不会牵动其他的。
19. As a 开发者，I want Fairy 的决策是可复现的（固定种子、固定步长），so that 同一个 bug 能重放。
20. As a 开发者，I want AI 有明确的每帧预算，so that 手机上掉帧时先知道是不是 AI 的锅。
21. As a 开发者，I want 一个无头战斗模拟器，so that 我不进编辑器也能跑几百场回归。
22. As a 调参者，I want 权重、候选数、视域集中在配置里，so that 调手感不用改代码。
23. As a 验收者，I want 有「Fairy 在可存活场景里必须存活」的断言，so that 代行不会在演示时翻车。

## Implementation Decisions

### 1. 导航层（以骸与 Fairy 共用）

- **网格**：1 单位（32px）一格；由关卡的障碍物烘焙可走性；角色半径 0.4 单位，可走格需留出通行宽度。
- **邻接**：8 邻接，对角代价 √2，**禁止贴角穿越**（两个正交邻格都不可走时禁止对角）。
- **流场**：从玩家位置做 Dijkstra，记录每格到目标的距离与梯度；**每 0.25s 重算一次**，追兵只读梯度，不各自跑 A*。
- **A\***：定点寻路（Boss 接近、钉枪重新站位、Fairy 候选点）；每帧最多 4 条，超出排队。
- **平滑**：路径做视线拉直（string pulling），再交给转向层。
- **转向**：朝向目标的速度插值 + 分离力（同类之间最小间距 0.6 单位）+ 障碍滑行；**不做物理刚体推挤**。
- **更新频率**：导航 4Hz；转向 60Hz。

### 2. 以骸行为状态机

| 以骸 | 寻路方式 | 状态机 |
| --- | --- | --- |
| 尾灯 | 流场追玩家 | `Approach`（常驻）、`Death` |
| 撞针 | A* 接近到冲刺距离 | `Approach` → `Windup`(0.6s 静止+预警) → `Dash`(直线 0.25s，撞墙停) → `Recover`(0.8s) → `Approach` |
| 钉枪 | A* 重新站位 | `Reposition`（维持在 5–7 单位环带）→ `Aim`(0.5s，需视线) → `Fire` → `Recover`；玩家 <3 单位时 `Retreat` |
| 坠物 | 无地面寻路（飞行） | `Hover`（空中跟随，受空域分离）→ `Mark`(在玩家附近画 2×2 矩形) → `Drop`(1.2s 延迟) → `Impact` |
| 连环 | A* 接近 | `Approach` → `Windup`(1s) → `Dash`(0.4s) → `Recover`(1.5s)；≤50% 追加 `Summon`（每 8s，2 只钉枪，同屏 ≤4） |
| 骤雨 | 无（站桩） | `Idle` → 技能调度器（冷却 4s）：`Barrage`（6 块矩形，1 块必含玩家当前位置，3s 预警）或 `Summon`（≤60%：2 撞针 + 1 钉枪）；两技能**不重叠** |

- 所有以骸共用的约定：进入 `Windup` 必须有视觉+听觉预警；`Dash` 期间不转向；死亡立即停止碰撞伤害。
- **移速约束**：所有以骸移速 < 玩家移速（冲锋与冲刺瞬时速度除外），否则「不掉血」与「保持射程」无法同时成立。

### 3. Fairy 规划层

**输入**：世界快照（玩家位置/速度/半径/刀数/ω、敌人位置与状态、道具位置、导航图）。
**输出**：目标点 + 旋转方向 + 到达后保持的朝向。
**频率**：每 100ms 重规划；只执行最优路径的前 200ms，然后重评（滚动时域）。

#### 3.1 候选点生成（每轮 12–20 个）

- 每个敌人的「环带切点」：以玩家为圆心、半径 r ± 0.15 的圆弧上，取靠近该敌人的 2 个点；
- 每个道具的到达点；
- 远离最近威胁的安全点（沿威胁反方向）；
- 当前朝向的前方 0.5 单位（用于平滑，避免原地抖动）。

候选点做可走性过滤；不可达直接丢弃。

#### 3.2 评估（前瞻 1 秒，步长 0.1 秒）

对每个候选点，同时评估两个旋转方向 `s ∈ {+1, −1}`，再取更好的那个：

- **预测**：玩家按直线或 A* 前 2 段移动到候选点；敌人按各自状态机的简化规则推进（追兵沿梯度、冲锋按锁定方向、弹丸直线、落区按计时）；
- **伤害期望** `D(c)`：接触伤害 + 弹丸命中 + 落区命中，按 `hp` 归一；
- **环上驻留** `R(c)`：敌人在环带 `[0.85r, 1.15r]` 内的时间加权数量（按威胁加权）；
- **相对速度** `V(c, s)`：`Σ w_i · |ω + s·(m·t̂_i)/r|`；
- **道具收益** `I(c)`：路径上拾取物的价值 / 绕路代价。

#### 3.3 决策（字典序，不是加权和）

1. **P0 安全**：`D(c) ≤ 2% 最大生命` 的候选为安全集；安全集为空时选 `D(c)` 最小者（并允许微伤）。
2. **P1 射程覆盖**：在安全集内，保留 `R(c)` 不低于最优值 85% 的候选。
3. **P2 相对速度**：在剩余候选内取 `V(c, s)` 最大者。
4. **P3 道具**：当道具落在当前路径 1.5 单位内时，用 `I(c)` 作为最终平局决胜；否则忽略。

> 用字典序而不是加权和，是因为设计意图是「保命 > 压制 > 输出 > 顺手」，加权和会让某一项在极端数值下压过保命。

#### 3.4 方向切换

- 对同一候选点分别算 `s=+1` 与 `s=−1` 的 `V`，只有**相对更优超过 5%** 才切换；且距上次切换 ≥0.15s（与 0.1s 输入去抖叠加）。
- 切换不改变移动，只翻转角速度符号。

#### 3.5 执行与兜底

- 执行层用 A* 到候选点；被临时阻挡时沿障碍滑行，不重新寻路。
- 无安全候选且敌人贴脸：朝最近威胁反方向撤退（纯逃离），直到安全集非空。
- 候选全部不可达：保持当前朝向小幅移动（防抖）。
- 卡住检测：0.5s 位移 <0.1 单位则强制换候选点。

#### 3.6 预算与复现

- 每帧 AI 预算 ≤2ms（中端机）；候选数随同屏敌人数自适应：≤10 敌 20 个，≤40 敌 12 个。
- 固定步长 0.1s、固定随机种子；候选抖动由种子驱动，重放可复现。
- 调试叠层：候选点、路径、`D/R/V` 分量、当前选择，默认关闭。

### 4. 配置项（可调，不写死）

| 参数 | 默认 |
| --- | --- |
| 重规划间隔 | 0.1s |
| 前瞻时长 / 步长 | 1.0s / 0.1s |
| 候选数 | 12–20（自适应） |
| P0 微伤阈值 | 2% maxHP |
| P1 保留比例 | 85% |
| 方向切换阈值 / 最小间隔 | 5% / 0.15s |
| 导航重算 | 0.25s |
| 空域分离间距 | 0.6 单位 |

### 5. 复刻协议

原型的价值在于「可复刻」：同一个场景 + 同一个种子，换一次运行、换一个人跑，结果必须一致。

- **固定步长**：模拟按 1/60s 推进；AI 决策固定 0.1s（每 6 帧一次）；模拟内禁止读 `Time.deltaTime`。
- **自研运动学**：位置、碰撞、伤害全部在纯 C# 里算，**不用 Unity Physics / Rigidbody**——物理求解器的接触求解不可复现。
- **种子**：候选抖动、召唤位置、落区随机全部走一个显式 `Random`，种子写进场景文件。
- **场景文件**：JSON，含关卡、玩家初始状态、敌人刷新序列（时间 + 位置 + 类型）、时长、期望指标。
- **回放文件**：每 tick 记录 `{tick, seed, playerCmd, fairyCmd, enemyStatesHash}`；哈希用于跨运行比对。
- **指标**：存活、掉血、命中数、击杀数、平均环上敌人数、单帧决策耗时，写到 `results/<scenario>-<seed>.json`。
- **一键运行**：`dotnet run -- --scenario <file> --seed <n>`（或等价的 batchmode 入口），不需要打开编辑器。
- **通过标准**：同机同种子两次运行，命令日志逐 tick 相同；跨机允许浮点末位差异，但指标偏差 <0.1%。

原型交付三件事：无头模拟器、调试叠层、三个基准场景（单敌人、四敌混战、Boss 战）。调试叠层可以后补，前两件是硬要求。

## Testing Decisions

- **唯一接缝**：无头战斗模拟器 `BattleSim`——固定步长推进世界，注入以骸与 Fairy，只依赖 `BattleSnapshot` 与 `Command`。所有行为测试都从这一层进，不测 MonoBehaviour 内部。
- 单元测试（EditMode）：
  - 导航：绕墙、不贴角穿越、不可达返回 null、流场梯度指向玩家；
  - 撞针状态机：`Windup` 时长、`Dash` 不转向、撞墙停止、`Recover` 后可再次接近；
  - 钉枪：保持环带、无视线不开火、贴身撤退；
  - 坠物：落区在玩家附近的矩形、1.2s 延迟；
  - Boss：连环召唤上限 4、骤雨技能间隔 ≥4s 且不重叠、必有一块落区含玩家位置。
- Fairy 断言（黄金场景，固定种子）：
  - 可存活场景中 4 秒内掉血为 0；
  - 单敌人站桩场景中，代行期间的命中数高于「直线绕圈」基线 ≥20%；
  - 两个方向中必选 `|ω_rel|` 更大者（容差 5%）；
  - 同一快照重放两次，输出完全一致。
- 性能测试：40 个追兵 + 1 Boss + Fairy，单帧 AI ≤2ms（开发机基准，中端机按 2× 折算）。
- **复刻测试**：同场景同种子跑两次，逐 tick 命令日志的哈希完全一致；若跨机器，指标偏差 <0.1%。
- 回归：`BattleSim` 场景文件（种子 + 关卡 + 敌人序列 + 期望结果），一条命令跑完并输出 `results/*.json`，CI 可跑。
- 先例：与美术、音频规格共用「纯 C# 接缝 + EditMode」的做法；本规格是新代码的第一批测试。

## Out of Scope

- 玩家控制手感、镜头、动画与表现。
- 网络同步、多人。
- 机器学习/神经网络驱动的 AI（本项目不用）。
- 关卡生成与难度曲线（属于关卡数据）。
- 音频与视觉预警的具体素材。

## Further Notes

- **「智能不是开挂」的硬约束**：Fairy 只能读玩家也能看到的信息，只能做玩家也能做的动作（移动 + 切向），速度/半径/攻击与玩家完全一致；不允许无敌帧、加速、传送、伤害加成。
- **已知失效模式**：开阔场地风筝到天荒地老（P0 永远安全但 P1 不满足）。缓解手段是关卡结构（掩体、走廊）与「敌人移速 < 玩家」的数值前提，不靠改算法。
- **与伤害公式的关系**：`hits/s = N·|ω_rel|/2π`，`ω_rel = ω + s·(m·t̂)/r`。P2 的最大化目标就是这个式子的加权和；这也是「顺着刀刃切向走」的数学来源。
- **调参顺序**：先调 P0 阈值与候选数（决定「像不像人」），再调 P1 保留比例（决定「压不压制」），最后调方向切换阈值（决定「炫不炫」）。
- **性能红线**：如果 40 敌场景超预算，先降导航重算频率（0.25s→0.5s），再降候选数，不要砍前瞻步长——前瞻变粗会让 Fairy 看起来突然变笨。
